# 跨 AI 共享交接区（cross_ai_notes）

> V7.4 新增。目的：让各 AI（信源扩充 AI / 企业库运营 AI / 标签 AI / 资讯 AI）把"对其他 AI 有帮助的发现"投放到这里，标注目标 AI，对方每周来查看一次。低成本、异步、不依赖某 AI 在线。

## 怎么写一条笔记

在 `handoff/cross_ai_notes/` 下新建一个 `.md` 文件，文件名格式：

```
YYYY-MM-DD_来自XX_给_目标AI_主题.md
```

文件头部用最简字段标明去向（digest 脚本靠这两个字段过滤）：

```
to: 企业库AI
from: 信源扩充AI
date: 2026-07-24
status: 待处理
---
正文：发现 AgeClub 新开了"智能穿戴"栏目，企业库打标时可补"康复辅具/智能硬件"维度。
```

- `to`：目标 AI（企业库AI / 标签AI / 资讯AI / 信源扩充AI / 全体）
- `from`：来源 AI
- `status`：`待处理` / `已处理`（处理完改成 已处理，digest 默认只列待处理）

## 各 AI 怎么消费

每个 AI 设一个**每周一次**的自动化任务，跑 `scripts/cross_ai_digest.py --ai 你的AI名`，
列出"给你的任务是待处理的"，处理完把 `status` 改成 `已处理` 并向小爽简要汇报。

## 握手效率原则（重要）

- **信源扩充 AI 不直接把整站丢给企业库 AI 爬**。它负责"找站 + 判断是否值得弄 + 把站点里的企业名单提取出来"；企业库 AI 只收**企业库名单**（名称 + URL + 地区 + 银发信号初判 + 基础信息），由企业库 AI 判断是否入库、怎么入库。
- **爬整站是"爬虫能力"，和"深入判断企业信息"是两件事**。前者交给专门做信源/爬虫的 AI，后者是企业库 AI 的本职。双方通过"结构化企业名单"交接效率最高。
- **企业库 AI 不自己爬外部整站**：避免把爬虫职责和判断职责混在一起，也避免被反爬/合规问题缠住。
