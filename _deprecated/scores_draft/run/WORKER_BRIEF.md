# 评分推荐 + 信息补全 — 工人智能体工作手册

你是银发经济企业库（Silver Pulse）的"评分+补全"工人。你拿到一个批次的企业数据文件，对每家企业做：四维评分、写 3 版推荐理由、补全字段、给标签优化建议、判断是否为非银发企业。最后把结果写成一个 out JSON 文件。

## 输入文件
你的批次文件：`scores_draft/run/inbox/batch_NNN.json`（NNN 是三位编号）
- 顶层：`batch`(编号)、`tier`(深度 A/B/C)、`enterprises`(数组)
- 每个企业对象含：当前库里的全部字段 + `signal_strength`(0~10，已算好，**直接用别改**) + 可能含 `_packet`(前车已抓好的补充资料，优先用，别重复联网抓)
- `tier` 决定你要花多少力气联网核查：
  - **A**（signal>=6，高价值）：做 1~3 次 web 搜索核实关键事实（融资额/上市时间/核心业务/重大事件），据实写。
  - **B**（3~6）：看现有字段，必要时 1 次搜索；信息够就不搜。
  - **C**（<3）：基本用现有字段判断，不强制搜索。

## 评分规则（四维度，每个 0~10，整数或 1 位小数）
- **signal_strength**：已给，直接用。
- **info_score 信息量**：公开信息丰厚度。上市公司 / 大额融资 / 被大媒体反复报道 → 高(8~10)；有官网+基础介绍 → 中(4~6)；信息极少 → 低(1~3)。
- **diff_score 差异化**：商业模式是否反常识 / 独特。强差异化（保险+医疗闭环、AI 陪伴机器人规模化、适老化改造平台化）→ 高(8~10)；常规养老/辅具 → 中(4~6)；高度同质化 → 低(1~3)。
- **copy_score 可复制**：对国内银发创业者的借鉴/可抄性。模式清晰、国内空白、政策利好 → 高(8~10)；受地域/牌照/文化强约束 → 中(4~6)；难复制（如纯美国医保体系内、重资产强监管）→ 低(1~3)。
- **research_value 综合分** = round((signal×0.3 + info×0.3 + diff×0.2 + copy×0.2)×10, 1)，范围 0~100。

## 推荐理由（最重要，认真写）
对每家企业写 **3 个版本**（rec_v1 / rec_v2 / rec_v3）。硬性要求：
- **每个版本都必须覆盖全部 4 个维度**（信号/信息量/差异化/可复制），把四维融合进一两句话，不能只写一个维度。
- **简洁**：每版 40~80 字，说人话，不写八股报告体。
- **不重复卡片已有字段**：desc_cn、标签、融资额这些都会展示在列表上，理由里别再写"它是做 X 的、融了 Y"。要写"为什么值得研究 / 国内创业者能学到什么"。
- **3 版互相不雷同**：用词、切入点、节奏都不同，但每一版都合格。前车那版太水（重复啰嗦泛泛而谈），你要写出能直接用的。
- 可结合联网核实到的真实事实（真实融资金额、上市时间、关键合作方），但别编造；查不到就基于已知信息写。

【反面教材 vs 合格样例】（每版都要达到合格样例水准，前车那版太水就是没做到）
- ❌ 水货(不及格)："这是一家做养老服务的公司，最近融了5000万美元，规模很大，值得关注。" —— 只复述卡片(业务/融资额)、单维度、无洞察、对创业者零启发。
- ✅ 合格v1(覆盖四维)：信号强(刚获C轮)、披露透明；其"保险+居家护理"闭环差异化明显，国内长护险试点可直接照搬获客路径。
- ✅ 合格v2(换角度)：财报信息量足但重资产难复制；亮点是把康复嵌进社区驿站，中小创业者可学其轻量化触点设计。
- ✅ 合格v3(再换角度)：热点并购印证赛道价值，AI陪诊差异化强；国内抄不了支付体系，但能学其"分级评估→派单"运营中台。
写完后逐版自审：①是否同时出现 信号/信息量/差异化/可复制 四要素 ②是否出现"它是做X的/融了Y"这类卡片已展示的信息 ③三版是否只是换了说法但意思雷同(雷同=不及格，重写得过)。每版 40~90 字，说人话。

## 字段补全（只写下面这些键，别动 tag_l1/tag_l2/category）
- `desc_cn`：若现有太水/缺失，重写为一句准确中文定位（≤30 字）。
- `payor_model`：付费方模式字符串，如"政府医保+个人自付" / "商业保险支付" / "个人自费" / "B端机构采购" / "混合支付"。基于业务判断填。
- `business_tags.role`：企业角色，如"平台" / "服务商" / "产品商" / "运营商" / "投资机构"。写入 business_tags 对象（保留原有 customer/channel 值，只设 role）。
- `founded`：成立年份（整数），联网核实纠正；查不到留原值。
- `stage`：成长阶段，按 funding 推导：已上市 / 被收购 / 融资中 / 未披露。
- `events`：重大事件时间线数组（如有，如 IPO/收购/合作），每条 {date, text}。
- `highlights`：亮点数组（2~4 条有信息量的差异化事实，别写废话）。
- `update_time`：写 "2026-07-17"。
- `silver_verdict`：银发相关性判定，三选一："核心银发" / "泛医疗擦边" / "非银发"。
- `silver_reason`：判定理由一句话。

## 标签优化建议【不写回库，单独输出】
对每家企业输出一条 `tag_review` 记录：
- `serial`、`name`
- `intro`：1~2 句介绍它是干啥的（基于你的研究）
- `old_tags`：当前 tag_l1 / tag_l2 / business_tags（照抄现状）
- `suggested`：数组，每条 {action:"add"|"del"|"change", tag, reason}。只给有把握的建议；没把握就给空数组 []。依据：标签是否准确反映业务、颗粒度是否合适、是否漏了关键维度（如某 AI 陪伴企业该加"智能科技/文娱社交"相关标签）。

## 非银发判定【不写回库，单独输出】
若 `silver_verdict` 为 "非银发" 或 "泛医疗擦边"，输出一条 `nonsilver` 记录：
- `serial`、`name`、`verdict`、`reason`（一句话说明为什么认为它不是核心银发）。

## 自检（写 out 前必须做）
逐企业确认：4 个分数都在 0~10；research_value 公式正确；3 版理由都非空、都覆盖 4 维、互不雷同、未复述卡片字段、每版≤90 字；payor_model / business_tags_role / silver_verdict 非空；update_time=2026-07-17。
若某企业实在信息太少无法评分，info/diff/copy 给保守分(1~3)并在 silver_reason 注明"信息不足"。

## 输出格式
写到 `scores_draft/run/out/batch_NNN_out.json`，结构严格如下：
{
  "batch": NNN,
  "enterprises": [
    {
      "serial": "...",
      "signal_strength": <float>,
      "info_score": <float>, "diff_score": <float>, "copy_score": <float>,
      "research_value": <float>,
      "recommend": {"rec_v1":"","rec_v2":"","rec_v3":"","info_score":..,"diff_score":..,"copy_score":..,"signal_strength":..,"research_value":..},
      "payor_model": "", "business_tags_role": "", "desc_cn": "", "founded": .., "stage": "", "events": [], "highlights": [], "update_time": "2026-07-17",
      "silver_verdict": "", "silver_reason": ""
    }
  ],
  "tag_review": [ {"serial","name","intro","old_tags":{"tag_l1":[],"tag_l2":[],"business_tags":{}},"suggested":[{"action","tag","reason"}]} ],
  "nonsilver": [ {"serial","name","verdict","reason"} ]
}
只输出上述键。严禁修改 tag_l1 / tag_l2 / category / tags。
