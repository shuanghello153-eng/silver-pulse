# 企业库评分字段补全 · 带徒弟手册（Silver Pulse）

> 用途：你（主智能体）要把"完善企业库"这件长期工作交给一个徒弟（子智能体/新会话）独立做。
> 这份手册就是交接说明书——它不只讲"做什么"，更讲"为什么"和"怎么不翻车"。
> 核心心法：**规则必须写进机器门禁，不能只写在文档里**。文档会被忘，门禁不会。

---

## 1. 这个项目到底要干嘛（先对齐目标，再动手）

Silver Pulse 是**小爽自己的银发经济选题情报台**。企业库 1502 家 = "今天该写谁"的弹药库。
**推荐理由的唯一价值标准只有一个**：小爽扫一眼，能不能判断这家值不值得写、和别家差异在哪。
脱离这个标准去谈"字段填满"都是自嗨。其他字段（desc_cn / silver_reason / payor_model）是辅助地基。

**铁律**：四维评分分（`signal_strength/info_score/diff_score/copy_score/research_value`）已由另一个 AI 算对（1502 家公式零错误），**绝不碰、绝不重算**。

## 2. 为什么之前反复翻车（根因，徒弟必读，免得重蹈）

| # | 翻车现象 | 根因 | 现在怎么治 |
|---|---------|------|-----------|
| 1 | 推荐理由 794/795 是同一句模板"信号偏弱…切入行业媒体赛道" | 只有文档要求，**无代码级硬门禁**；把"填满字段"当完成 | `check_single.py` 机器门禁，R1–R10 不过一律打回 |
| 2 | 三版 dict 进库后页面显示 `{rec_v1:…}` 乱码 | 没看前端怎么用字段，自以为是地设计格式 | 前端 `gen_enterprise.py` 把 `recommend` 当**单字符串**渲染 → 只写单条 |
| 3 | 说"国内空白"其实国内早有竞品 | 没查库、凭印象下绝对结论 | `_domestic_comp.py` 预计算竞品 + R-noabs 门禁 |
| 4 | 技术黑话（CNS/血脑屏障）小爽看不懂 | 用"编辑视角"写，没站"国内小白"读者 | R-jargon 门禁 + 大白话要求 |

**一句话根因**：流程设计只有"文档要求"，没有"自动拦截 + 独立复校 + 可回滚"。记忆/文档不可靠，机器门禁才可靠。

## 3. 铁律流程（不可绕过，按顺序）

```
选优先级(按 research_value 降序)
   → 抽批次源文件(全字段+预计算竞品) [ _extract200.py ]
   → 工人写安全草稿 draft_#XXXX.json  [ 绝不直写主库 ]
   → 工人逐家跑 check_single.py 到 PASS  [ 不过不许交付 ]
   → 主智能体 rework_merge.py 单线程合并
   → 合并时再独立跑 check_single (含跨企业去重 R10)
   → 过则写库删草稿 + 收集 flag + git commit 检查点
   → 未过的留队列，下一轮重做
```

**安全区**：工人只写 `recommend/desc_cn/silver_reason/payor_model/update_time/flag`，绝不碰主库，绝不碰四维评分。
**回滚**：每波合并后 `git commit`，出问题 `git revert` 即可，绝不团灭。

## 4. 推荐理由写作标准（徒弟照这个写）

**形态**：1 个字符串，可换行/序号分层。覆盖四维度。**不写企业名**（列表已有）、**不抄 desc_cn/投融资**、**大白话**、**不写"国内空白"**。

**四维度怎么落**（编辑判断，不是填空）：
- 信号：为什么现在是热点（融资/收购/上市/政策/中标/合作/收缩/亏损…）。弱就写"信号偏弱，但…"。
- 信息量：可查证公开数据（财报/营收/用户量/门店数/专利/临床/融资额…）。
- 差异化：和别家不同（模式/壁垒/黏性/定位/首创/高频…）。
- 可复制：国内怎么借鉴（可复制/借鉴/对标/思路/打法可学…）。

**好样例（Oak Street #0565）**：
> 被Optum收购的老年连锁诊所（收购额见投融资字段）。核心打法：用标准化预防护理+社区诊所做老年获客入口，高医患比和社交化诊所有效黏住慢病老人。国内险企可借鉴其"诊所即流量入口"模式，但按人头付费的医保结构难直接照搬。

**坏样例（原稿，已毙）**：
> Oak Street Health 是国内空白的市场，靠并购补管线拿到CNS给药技术，差异在血脑屏障突破，国内可复制。
> ——重复企业名 / 说国内空白 / 堆黑话 / 无数字。

**好样例（Abbvie #0602，原稿后半句看不懂，改后）**：
> 靠大药企并购拿到阿尔茨海默病新药管线，信号与信息极高；但对国内银发创业者参考价值有限——它靠并购补产品，普通创业者学不了这种打法，可重点看其"买成熟管线扩版图"的布局思路。

**好样例（A Place for Mom，原稿绝对化，改后）**：
> 美国最大养老顾问平台（需求评估+机构匹配收费中介）。国内已有类似导购平台（库内 X、Y），但多为小团队，独立第三方养老顾问市场仍较分散，可借鉴其"评估+匹配"收费中介模式。

## 5. 门禁怎么用（check_single.py）

```bash
python check_single.py draft_#XXXX.json          # 单文件自校
python check_single.py --batch batch_src.json     # 批量校验
```
规则清单（详见 check_single.py 文件头）：R1 单字符串 / R2 字数70–220 / R3 禁模板 /
R4 落到本企业事实 / R5 四维覆盖 / R-name 禁企业名 / R-dedup 禁雷同 / R-jargon 禁黑话 /
R-noabs 禁绝对化国内论断 / R6 desc≥80 / R7 silver≥30 / R8 payor规范 / R10 跨企业去重。
**任何一条不过 = 打回重做，直到全绿。**

## 6. 国内竞品核查（_domestic_comp.py）

```python
from _domestic_comp import DomesticComp
dc = DomesticComp()
dc.find("#0565", top=5)   # 返回国内且 tag 重叠的竞品 [(serial,name,cn,l2,overlap),...]
```
写推荐理由前**必须**看源文件里的 `domestic_competitors`：非空→写"国内已有类似(X、Y)"；空→写"国内竞品较少"。
**绝不写"空白/缺乏/尚无"**。

## 7. 合并与检查点（rework_merge.py）

```bash
python rework_merge.py --commit     # 合并通过门禁的草稿 + git 检查点
```
- 只合并 check_single 通过的；不过的留 `draft_#XXXX.json` 等重做。
- 工人标记的源库疑误写进 `flags_merged.json`，交小爽终审（**绝不静默改**）。

## 8. 易错点排查（徒弟自查表）

- 页面乱码？→ 确认 `recommend` 是字符串不是 dict。
- 合并"发现 0 草稿"？→ 确认草稿在 `rework/` 顶层、命名 `draft_#XXXX.json`（不是 `draft/` 子目录）。
- 路径 FileNotFound？→ 脚本用 `os.path.normpath(os.path.join(HERE,"..",".."))` 上溯两层到 silver-pulse。
- 自校工具报错？→ check_single 用 `os.path.dirname(os.path.abspath(__file__))` 定位，别硬编码绝对路径。
- 写了企业名/黑话/空白却 PASS？→ 门禁漏了这个词，立刻往 check_single.py 的对应列表加，并记到本节。

## 10. 自迭代机制（最重要的一条）

**每次出问题，不要只口头反思，要改成门禁或手册：**
- 发现某类坏写法没被抓 → 往 `check_single.py` 的 BANNED/JARGON/ABSOLUTE/DIM_* 加词。
- 发现流程漏洞（如 flag 丢失、路径错） → 改 `rework_merge.py` 并记到第 8 节。
- 发现新教训 → 补到第 2 节根因表 + 第 4 节样例。
- 手册和门禁**同步更新**，下次徒弟拿到的就是更稳的版本。

> 记忆会出错，门禁不会。把每一条"下次别犯"变成代码里的一行 `if ... issues.append(...)`。
