## 6. 多 AI 选题 PK（我的看法）

你的思路完全可行，技术上叫 **Multi-Agent Debate**（arXiv 2305.19118）：多视角 PK 再由裁判汇总，能突破单模型"自我确认偏差"。但在 WorkBuddy 单会话里**没有原生群聊**，落地方式两种：

- **方案 A（单窗口内角色辩论）**：开一个"选题"窗口，指令它依次扮演 3-4 个视角（国内可比性 / 反常识差异化 / 投融资信号 / 用户需求），各自产出 TOP 选题，再自我汇总成终榜。优点：一个窗口搞定；缺点：本质是串行角色扮演，非真并行。
- **方案 B（多窗口 + 裁判）**：开 3-4 个"视角"窗口 + 1 个"裁判"窗口，各自返回结构化榜单，裁判按四维框架机械合并。优点：真并行、视角独立；缺点：你要手动开多个窗口、token 成本更高、需显式把结果回传裁判。

**我的建议**：先用**方案 A** 跑通**周更**选题工作坊（别做日更，成本太高），裁判 rubric 直接复用我们的四维框架（信号强度/信息量/差异化/可复制）。附可直接粘贴的"选题"窗口指令模板（见文末）。

**坑**：①同模型自裁判有确认偏差 → 裁判窗口加"反向找茬"步骤；②多轮 PK token 爆炸 → 设轮次/预算上限；③各窗口独立 → 结论要结构化回传，避免重复。

## 7. 问题发现机制（方案）

针对"用户会遇到哪些问题、怎样及时发现"：

- **线上监控（轻量）**：在 index/enterprise 页内联隐私友好的计数（PV、筛选无结果率、卡片点击热区）→ 输出到免费自托管分析或每日写 `run_logs`。先不接第三方，避合规风险。
- **报错捕获**：`window.onerror` → 写 localStorage + 每日自检时上报；6.7MB 解析失败能立刻发现。
- **用户反馈入口**：每页右下角加"报错/建议"浮窗，提交到 issue 或飞书。
- **每日自检日报**（已有 `validator.py`）：扩展为"数据新鲜度告警 + 评分维度健康度 + 渲染漂移 + 死链"，出中文日报。这正是"数据质量守护"窗口的活。
- **A/B 验证**：改 UI 前后对比"筛选无结果率/停留"，用数据证明改对了。
