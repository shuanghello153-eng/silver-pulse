## 0. 核心定调修正（来自小爽 2026-07-18 对齐）

**原方案（已作废）**：给每家企业写 `recommend = {rec_v1, rec_v2, rec_v3}` 三版，三版"合起来"覆盖四维度。
**新定调（正确）**：推荐理由 = **1 个字符串**，覆盖 `信号强度 / 信息量 / 差异化 / 可复制` 四维度，言之有物、彼此差异化、能支撑小爽做"今天写谁"的抉择。

为什么新定调才对（有据，非凭感觉）：
1. **符合用户目标本质**：推荐理由的唯一价值是"帮小爽从 1502 家里快速决断"。三版互不雷同只是增加了挑选成本，且每版都没覆盖全维度 = 没解决"信息完整"问题。
2. **与现有网站兼容（铁证）**：`gen_enterprise.py:149` 与 `:326-327` 把 `recommend` 当**单个字符串**直接插进企业卡片（`💡 推荐理由: {recommend}`）。三版 dict 一旦进库，页面会渲染成 `{‘rec_v1’:…}` 乱码。单条字符串才是正确格式。
3. **内部可多版思考、只落一条**：小爽原话"如果这样能有利于更好地思考，你可以自己看"——工人/AI 可内部用多版角度构思，但最终 `recommend` 字段只存 1 条综合理由。

## 1. 另一个 AI 工作评估（评分 + 维度 + 根因）

**综合评分：45 / 100。** 唯一做对的是评分公式（四维 + 综合分，1502 家零错误）。

| 评分维度 | 分 | 证据 |
|---|---|---|
| 完整性（字段是否填满） | 85 | 几乎全填，仅少数缺失 |
| 准确性（评分公式对不对） | 90 | research_value 公式零错误，这是亮点 |
| 可用性（推荐理由能否支撑选题） | 5 | recommend 0/1502 达标；795 条单字符串 794 条是"信号偏弱…切入行业媒体赛道"模板 |
| 一致性（跨企业不雷同、payor 可筛） | 10 | payor 293 种值、1193 条非规范；72 次跨企业重复同一句套话 |
| 校验闭环（自校验/独立校验） | 0 | 自写 `monitor_data_quality.py` 只 READ 不校验，门禁是假的 |

**为什么不达标（根因，五条全缺）**：
1. 没有代码级硬门禁（只有文档要求，无法自动拦截烂输出）。
2. 没有独立子智能体从多视角校验（自己写自己过）。
3. 没有用户视角走查（没站在"小爽早上刷选题"的场景测）。
4. 没有"任务完成自动触发校验"的机制。
5. 没有多轮自我纠错迭代。
→ 根因是**流程设计缺陷（无门禁）+ 需求理解偏差（把"填满字段"当完成，没理解"推荐理由要帮选题"）**。

## 3. 新门禁规则（validator 改造方向）

| 规则 | 旧（作废） | 新（V2） |
|---|---|---|
| R1 格式 | 必须 dict 含 rec_v1/2/3 | **必须是单条字符串，禁止 dict** |
| R2 长度 | 每版 40–90 | **单条 80–160 字**（覆盖四维度需空间，待拍板） |
| R3 禁模板 | 禁生成器套话签名 | 同左，扩到跨企业级 |
| R4 非 dict | — | 同 R1 |
| R5 维度覆盖 | 三版合起来覆盖四维度 | **单条命中四维度词族**（信号/信息量/差异化/可复制 各至少一关键词） |
| R6 desc | ≥80 | 同左 |
| R7 silver | ≥30 | 同左 |
| R8 payor | 规范词表 | 同左（11 项规范词） |
| R9 公式 | 正确 | 同左（已达标，仅监控） |
| R10 跨企业去重 | 无 | **新增**：与已合并库内 recommend 字符重合率 >0.6 即打回（直接服务"彼此差异化、能做抉择"） |
| R11 不复述卡片 | 有 | 同左 |

保留的硬机制（本回合已建、验证可用）：**安全草稿（只写 draft_#XXXX.json，绝不直写库）→ 独立 validator 判 → 不过打回 → 主智能体单线程合并 → git 检查点 → 用户视角抽 5 家走查**。

## 4. 工人流程（V2）

- 内部构思允许多版角度，但**最终只写 1 条综合 `recommend` 字符串**进草稿。
- 只写安全区字段：`recommend`(单条) / `desc_cn` / `silver_reason` / `payor_model` / `update_time` / `flag`。
- 优先用库内已有字段（tag_l1/l2、stage、funding、四维分、原 recommend 字符串）撰写，缺关键事实才补 1–2 次联网。
- `flag`：发现原库其他字段（融资额/阶段/上市状态）明显错，记此处交小爽终审，禁止静默改。
- 自校：写完后跑 `check_one.py` 到 PASS 才交付。
