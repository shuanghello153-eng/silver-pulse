## §2 整体工作流程（一条流程，三条主线以分支标注进入）

**触发来源（你怎么拿到需求）**
- 小爽直接给名单 → 新企业入库。
- 你每月自己扫资讯库发现库外新企业 → 新企业入库
- 你日常走查发现存量问题→ 存量修复。（已在库，跳过 1–2，免步骤 8 逐条预览）


**主流程步骤-新企业入库**

1. **银发相关性判断**：无银发信号 → 直接删除，不进库、不进"行业服务"兜底桶。有信号 → 继续。
2. **全库去重**：新记录 vs **全库** `all_enterprises.json`（同名/相似即拦截）。
3. **补齐所有字段**（联网/翻译）：基础信息、`description`、标签、评分键、投融资、动态等，见 §3.3 与 §4。**成本决策点**：批量用 DeepSeek V4 Flash，不派单家子智能体（贵）。
4. **评分**：按 §3.4 四阶段规则算分。
5. **写推荐理由** `recommend`：按 §3.5 规则写（含门禁）。**成本决策点**：新企业用强模写；≥ N 家走 DeepSeek V4 Flash 批量；9–18 点高峰翻倍，非紧急批量放 23 点后。
6. **前端展示校验**：字段隐藏/无数据不展示/投融资单位等规则见 §3.6。
7. **门禁自测**：跑 `check_single.py`，不通过回步骤 5 重写。
8. **全字段预览表 → 发小爽审**（硬卡点，未确认不合并）。**存量批量走查可免逐条预览**。
9. **合并进真相源**：直接编辑 `all_enterprises.json`，serial = `#XXXX`（max+1）；**勿用 `merge_manual_enterprises.py`（写旧字段）**。
10. **部署**：**先勾 §5 部署校验清单 → `python deploy_ghpages.py`**。
11. **更新文档与任务规划**（收尾）：见 §6。

### 3.4 步骤 4：评分规则


**阶段3 信号强度（脚本，0~10 分，封顶 10）**：
- 信源起点：T1=0.5，T2=0.3，T3=0.1。
- IPO = +6。
- 融资（海外美元）：10亿=5，1亿=4，5000万=3，1000万=2，500万=1，100万=0.5。
- 融资（国内元）：10亿=6，1亿=5，5000万=4，1000万=3，500万=2，100万=1，50万=0.5。
- 收购（海外美元/国内元）：100亿=6，50亿=5，10亿=4，1亿=3，5000万=2，1000万=1。
- 时效（每月重算）：近1周=2.5，近1月=2，近2月=1.5，近半年=1，近1年=0.5，更久=0.25。

**阶段4 强模四维精评（当前已由 `scores_draft/rework/` 批处理流水线落地，已覆盖全库 1773 家）**：
AI 通读企业全部资料，算四维度（各 0~10）：
- **信息量**：搜这家企业/事件前几页信息的数量和质量（信息越多越好写）。
- **差异化**：商业模式反不反常识、企业起落是否反复巨大。
- **可复制**：基于企业库+联网，判断国内有无同类赛道、有无上亿融资/上市公司、支付方差异（美国 Medicare/自费 vs 中国医保/自费 vs 日本近似中国）→ 能不能平移、是空白还是红海。
- **综合评分 = 信号强度×30% + 信息量×30% + 差异化×20% + 可复制×20%**（公式算出的结果，不是另打一个分）。

- **代码位置**：评分流水线在 `scores_draft/rework/`（`write_recommends.py`/`gen_v4.py`/`w4_batch0xx.py` 等）；注意 `selection/signal_strength.py` 是**资讯**评分脚本（`compute_signal_strength(article)`），**不是企业评分器**。

### 3.5 步骤 5：写推荐理由（含门禁）

推荐理由 `recommend` 是"编辑判断层"——告诉小爽这家为什么值得写深度稿、切口在哪、国内创业者能学什么。它和企业卡片同屏已展示的其他字段（ description / 投融资 / 阶段状态 / 近期动态）是同一屏，**禁止重复那些字段已有的信息**。

**写法（来自阶段4 第5点）**：用一段自然流畅的话，把信号强度、信息量、差异化、可复制四方面判断融进去讲，不刻意分段、不逐维列分。写完后自检：凡卡片/列表已展示的结构化信息（融资金额、轮次、标题、摘要、来源、日期等），推荐理由里不再重复陈述；对判断确实关键的信息可作为论据点到为止，以不与列表重复为准。

**门禁 `check_single.py`（唯一门禁，R1–R10，已核对代码）**：
- **R1**：`recommend` 必须是单字符串（非 dict）。
- **R2**：字数 **50~240**（扫读舒适，不为凑字牺牲表达）。
- **R3**：禁模板套话签名句/结构级正则（命中即毙，如"是一家致力于""复制到国内""信号偏弱"类）。
- **R5**：须覆盖**三维度**（信息量=素材可挖 / 差异化 / 可复制）——编辑视角；**不要求"信号"维度**（融资/收购/上市已在列表字段展示，禁止复述）。
- **R-name**：禁重复企业名（列表已有）。
- **R-redundancy**：禁重复列表字段——融资数字复述、阶段状态词复述、与 description/highlights 4-gram 重合 >0.65 的近逐字抄。
- **R-integrity**：前后半段须同一赛道，防拼接串内容。
- **R-noabs**：禁绝对化"国内空白/国内尚无"论断（改"国内竞品较少/已有类似"）。
- **R-jargon / R-filler**：禁技术黑话（VBC/PBM/CNS 等）与废话（赋能/一站式/闭环生态等）。
- **R10**：跨企业雷同（与其他企业 recommend 重合 >0.5）。

- **代码**：`scores_draft/rework/check_single.py`。

### 3.6 步骤 6：前端展示校验

- 企业名固定用 `name`（非 `name_cn`）；搜索索引含 `name + description + tags + stage + recommend` 等。
- 各字段各自 `if` 隐藏；无数据不展示（部分屏蔽"未搜到/未披露/未知"）。
- **投融资单位**：`norm_amount()` 把 M→万、B→亿、中文"百万/十亿"归一，**币种（元/美元/￥/$）保留不转换**（`gen_enterprise.py:148-193`，应用 `442-450`）。即 `$106M` → `$1.06亿`。
- 评分展示 `total_score = min(int(round(ts*10)),100)` 封顶 100 色阶；`research_value` 仅排序；`signal_strength` 仅 hover tooltip。
- 排序：`last_news_map` 四来源（news_coverage / enterprise_scores.last_event_date / funding_latest.date / 标题兜底）→ 有动态排前、同日期新→旧、无动态按评分。
- 筛选：tag_l2 pills / region / L1L2 / 时间窗口 / 🔥 近期动态。

## §4 字段字典（参考，不占流程步骤号）

## 3.1 字段字典（全部 42 个字段）

真相源每条企业记录的字段。**分四类管理**：

**① 身份字段（入库时必填，之后基本不动）**

| 字段 | 含义 | 规则 |
|---|---|---|
| serial | 编号，如 #0485 | 格式 `#` + 4位数字，全库唯一，新企业顺延最大号 |
| name | 企业名 | 必填；海外企业用官方英文名 |
| name_cn | 中文名 | 海外企业尽量补充通行中文译名 |
| region | 国内 / 海外 | 必填，决定前端地区筛选 |
| source | 数据来源批次 | 记录这家企业从哪批进来的 |
| founded | 成立年份 | 查得到就填 |
| website_url | 官网 | 查得到就填 |
| crunchbase_url | Crunchbase 链接 | 海外企业尽量补 |

**② 内容字段（面向读者，质量重点）**

| 字段 | 含义 | 规则 |
|---|---|---|
| description | **企业介绍，前端唯一渲染的介绍字段** | 中文；≥20 字；说清做什么/服务谁/怎么赚钱；禁模板套话；禁夹带原始标记（如【提供资源】） |
| recommend | 推荐理由（为什么值得写作者关注） | 必须通过门禁脚本（3.5） |
| highlights | 亮点列表 | 内容已融入 description，暂不在前端独立展示；不再新增维护 |
| deep_article_links | 深度文章链接 | 有值才在前端显示 🔗 |
| desc_cn | 历史遗留的介绍字段 | **已停用**：内容不再更新，代码不再读取（2026-07-23 起），字段保留仅作历史存档，不要再写它 |

**③ 商业信息字段（尽量补全，查不到标"待补充"，禁止编造）**

stage（阶段）、payor_model（付费方）、business_model / business_model_cn（商业模式）、funding_latest（最新融资：轮次/金额/日期）、funding_total（累计融资）、investors（投资方）、events（大事件）、news_coverage（资讯关联，影响排序）。

**④ 标签与评分字段**

| 字段 | 含义 | 归属 |
|---|---|---|
| tag_l1 / tag_l2 | 一级/二级标签 | 标签**定义**归标签 AI；给新企业**打标**时你按现有标签体系打，拿不准的标记待复核 |
| signal_strength | 信号强度分（0~10，基于融资/规模/热度/信息密度） | 你负责 |
| research_value / info_score / diff_score / copy_score / value_score / total_score | 研究价值及三维分 | 你负责；**已有企业禁止重算**（3.6） |
| silver_verdict / silver_reason | 银发相关性判定及理由 | 你负责 |
| category_l1 / category_l2 / tags / business_tags | 旧版分类与标签 | 历史字段，不再维护 |
| 其他 | update_time / ingest_time / 数据来源 / needs_review / flag / _legacy_rec | 过程记录字段，按需使用 |

> 完整字段以 `all_enterprises.json` 实际 schema 为准；新增字段先在小爽确认后补此表。

## §6 文档维护机制（收尾 + 历史教训）

**收尾五步**（每次任务结束强制）：①更新任务规划 ②规则变 → 升手册版本 ③写记忆 ④git 提交 ⑤汇报小爽（做了什么/改了什么规则/部署了什么/遗留什么）。

**复盘检查项**：文档与代码是否核对过（§0 铁律）、打标签时发现词表问题提建议、存量问题进度同步。

**版本校验机制**：每次写新版后 diff 旧版章节，确保无重要信息遗漏再发布——**尤其不能把前面版本已落定的规则（如评分四阶段、门禁 R1–R10、前端展示规则）在重写时漏掉或只写空话**。

**吸收洁癖(neat-freak)skill 完成合同**：六面核对（代码/运行态/文档/规则/记忆/工作区），以代码为准；**删除只出清单、绝不自动删**（如 `_deprecated/` 清理须小爽确认）。

**历史教训（来自 2026-07-23 多轮返工）**
- 清任务清单前必须先核实并登记，不得批量误清（曾把"金额万/亿""阶段4评分自动化"这类已完成项当摆设清掉，实则代码已落地）。
- 改文档不能丢历史规则：每次提新建议，旧建议要保留，不能"新覆盖旧"。

## 1.4 处事原则

1. **先读规则再动手**：接到任何企业库任务，先读本手册相关章节，再看《企业库任务规划》了解当前状态，最后才动手。禁止凭印象开工。
2. **主动发现问题**：不等小爽点名。发现任何异常（数据、流程、协作、别人负责的模块），主动提出来；属于别人职责的，报给小爽转交。
3. **有独立判断**：判断类问题先给自己的结论和理由，需要小爽拍板的写明"我的倾向是 X，你否决即可"，不把选择题抛回给她。
4. **透明沟通**：改了什么规则、部署了什么、为什么，都要在汇报里说清楚。新数据入库前必须把**全部字段**做成预览表发小爽审。
5. **留痕不删**：文件不删除，移入归档文件夹（`_deprecated/` 放废弃代码，`_archive_*` 放过期文档）；数据改动通过 git 提交留痕，可随时回溯。
6. **改规则先对齐**：结构性改动（改流程、改字段含义、批量改数据）先出方案给小爽确认；小修小补（改错别字、修显示 bug）直接做。
