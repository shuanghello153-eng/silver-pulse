# 工人操作手册 V4（2026-07-18 紧急升级）

## 你的任务
对分配到的每家企业，写出**一条推荐理由(recommend)**字符串，必须通过 V4 门禁的全部规则。

## ★★★ V4 三条新铁律（旧版没有、本次新增、最高优先级）★★★

### 铁律1：R-field-dedup 全字段去重 — 推荐理由不能抄卡片上任何已有字段

**禁止**从以下字段大段照搬（≥10字连续相同即触发）：
- `desc_cn`（企业描述）
- `silver_reason`（银发理由）
- `highlights`（亮点列表任一条，≥8字）
- `funding_latest.display` / `funding_total.display`（融资展示串，≥8字）
- `description`（英文描述）

**正确做法**：读完全部字段后，合上"资料卡"，用自己的话重新组织分析。推荐理由的价值在于**你的判断和洞察**，不是把 desc_cn 改写一遍。

**常见错误模式**：
```
❌ "北美最大殡葬与墓园连锁，在全美运营2000多处设施、每年服务约30万家庭…"
   （前半段=desc_cn原句搬运）
✅ "被以106亿美元收购的老年社区诊所网络，信号强、收购披露充分。打法是用社区诊所做老年获客入口…"
   （有独立视角：收购价+获客打法分析，不是复述描述）
```

### 铁律2：R-integrity 内部一致性 — 前后半段不能讲不同企业

**检测方法**：系统会把推荐理由切成两半，分别提取赛道关键词。如果前半讲"殡葬"、后半突然跳到"远程康复"，说明你拼接错了内容或串了另一家的信息。

**正确做法**：写完通读一遍，确认整段在讲同一家企业的同一业务主线。

### 铁律3：R-novelty 增量信息 — 推荐理由必须有70%以上是独立分析

如果去掉推荐理由中与所有已有字段重复的部分后，剩下的新内容不到30%，说明你只是在抄。

**正确做法**：推荐理由应该包含这些"只有推荐理由才有的内容"：
- 四维判断（信号强弱/信息量是否充足/差异化在哪/可复制性如何）
- 对小爽选题的具体建议（"适合写深度报道"/"可做对比案例"/"暂存观察"）
- 与同类企业的横向比较（"比X更偏B端"/"国内类似Y但模式更轻"）
- 风险提示（"依赖政策补贴"/"盈利模式未验证"）

## 继续遵守的 V3 规则（不变）

### 格式规则
| 规则 | 要求 |
|---|---|
| R1 | recommend 必须是**单字符串**（不是dict！前端会炸） |
| R2 | 字数 70~220 字（去空白），建议 120~170 |
| R4 | 必须包含**数字** 或 **标签词**(tag_l1/tag_l2)，落到具体事实 |
| R-name | **禁写企业名**（列表已显示，写了浪费空间） |

### 质量规则
| 规则 | 要求 |
|---|---|
| R3 | 禁模板套话（"是一家致力于"/"信号偏弱信息量一般"/切入XX赛道等） |
| R5 | 单条覆盖四维度：**信号**(融资/IPO/事件)、**信息量**(数据/财报/规模)、**差异化**(独特/壁垒/少见)、**可复制**(国内平移/借鉴/对标) |
| R-jargon | 禁技术黑话（CNS/VBC/DRG/PBM/HMO等），小白看不懂必须换成大白话 |
| R-noabs | 禁绝对化"国内空白/缺乏/尚无/独家垄断"。查库内竞品后写"国内竞品较少/已有类似X" |
| R10 | 不与其他企业推荐理由雷同（跨企业重合率≤0.5） |

### 字段质量规则（如发现以下字段不达标也请顺手修）
| 字段 | 最低标准 |
|---|---|
| desc_cn | ≥80字，不以"是一家/致力于/专注于"开头 |
| silver_reason | ≥30字 |
| payor_model | 必须是规范值（见下方词表） |

payor_model 规范词表：个人自费 / 个人自费+政府补贴 / 个人自费+长护险 / 个人自费+医保 / B端机构采购 / B端机构采购+个人自费 / B端机构采购+政府付费 / B端机构采购+政府/商保支付 / 政府医保/商保支付 / 混合支付 / 不适用（投资机构）/ 未搜到

## 输出格式

每家企业输出一个 JSON 文件：

```json
{
  "serial": "#0565",
  "recommend": "被以106亿美元收购的老年社区诊所网络…",
  "desc_cn": "（如果原desc_cn<80字则补写到≥80字，否则保留原值）",
  "silver_reason": "（如果原<30字则补写，否则保留）",
  "payor_model": "（如果不规范则归一化，否则保留）",
  "flag": "（可选：发现源数据错误时记录，如'funding金额疑似错误'）"
}
```

文件命名：`draft_<serial>.json`，存入当前工作目录。

## 写作流程（每家企业必走）

1. **读完所有字段**（desc_cn / silver_reason / highlights / funding / tags / scores）
2. **合上资料卡**，想30秒：这家企业最值得写的1个点是什么？最该提醒小爽注意的风险是什么？
3. **写初稿**，控制在120~170字
4. **自检**：逐条过 R1-R10 + 三条V4新铁律
5. **改到过**再交下一家
