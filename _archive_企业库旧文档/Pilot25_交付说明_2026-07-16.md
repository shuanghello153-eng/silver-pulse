## 四、规划与理由：哪些做、哪些不做，为什么

### ✅ 做（补全）—— 理由
这些字段是"评分 + 推荐理由"的**直接产物**。我在写评分和理由时已经联网搜了大量企业信息，顺手把事实回填这些字段，**边际成本极低、产出极高**：
- `funding_latest` / `funding_total` / `investors`：纠正旧库"amount 填成投资方名"的硬伤，直接决定"是不是热点"判断。
- `payor_model`：**国内借鉴最关键差异点**（美 Medicare/自费 vs 中国医保/自费），不填这维度，推荐理由就成了空话。
- `founded` / `desc_cn` / `highlights`：纠正错填、替换模板废话，让卡片和理由有事实底座。
- 四维 + `research_value` + `recommend` + `update_time`：本轮核心交付，按文档1 四阶段产出。
- `value_score`：桥接写 = research_value，纯为旧前端回退兼容，保证不崩。

### 🔴 不做 / 废弃 —— 理由（结合你之前给的决策）
1. **`business_model` / `business_model_cn`（废弃，不主动重写 1210 条）**
   - 文档1 明标⚡️已废弃；

   - 你点明：它"大量重复、没辨识度、没价值"；
   - 推荐理由由"标签 + 联网研究"独立生成，**根本不读这个字段**。
   - 重写 1210 条自由文本 = 黑洞成本、零产出。**结论：留着旧值当 legacy，不碰。**

2. **`category_l1` / `category_l2`（废弃 / 不维护）**
   - 前端 `gen_enterprise.py` 分类徽章**早就改用 `tag_l1/tag_l2`**，这俩前端已不读；
   - 与 tag 体系重复，且另一 AI 在维护 tag；

3. **`tag_l1` / `tag_l2`（只读审查，不写回）**
   - 另一 AI 专职维护，我若写回必然冲突；

4. **`business_tags.role`（保留作输入，不主动补）**

   - 默认只读；只有高把握时才微调，且必标【动你标注】交你拍板。

5. **`description`（英文简介）/ `news_coverage`**
