## 1. 网站定位

Silver Pulse（银脉）= 银发经济投融资资讯聚合 **+ 企业数据库**，本质是小爽的**"选题情报台"**——让小爽一眼看到"今天哪些企业 / 资讯值得写深度稿"。

> 它不是资讯汇编站，是给小爽自己用的**选题决策工具**。每家企业 / 每条资讯的终点问题都是：中国银发经济创业者能从中借鉴什么？

## 4. 整体工作流程

### 4.1 概括

所有任务走**同一套流程**，只是「从哪进、走到哪停」不同。不存在多套独立流程。

### 4.2 任务前（每次任务先做两件事）

1. **更新任务规划**：打开 `企业库任务规划_V*.md`，完成移「已完成」、新增登「进行中」、遗留登「待办」。
2. **读最新手册**：确认当前最新版手册版本号；如果发现手册规则有变化（比如你上次任务改过），按变化程度自行判断是否需要走收尾里的升版本动作——**不需要每次都检查，AI 自行判断即可**。

### 4.3 需求来源

| 来源 | 走哪条流程 | 说明 |
| --- | --- | --- |
| **A. 小爽给企业名单** | → 完整 1→11 步 | 最常见 |
| **B. 每周资讯扫描发现** | → 并入 A（完整入库步） | 每周日 23:00 自动化扫描 |
| **C. 存量走查发现问题** | → 从步骤 3 起 | 准入/去重已做过 |
| **D. 外部 AI 交接** | → 信源扩充 AI 交来企业名单 | 见附录 A |

- **轻量分支**：纯 UI/UX 小改动可走「前端校验 → 直接部署 → 事后补审」，不必走完整审核关卡。

### 4.5 编排脚本与防卡住

**编排脚本** `scripts/enterprise_build.py`：
```
python scripts/enterprise_build.py --candidates 候选.json            # 门禁自测（不合并）
python scripts/enterprise_build.py --candidates 候选.json --merge    # 门禁→备份→增量合并→生成
python scripts/enterprise_build.py --candidates 候选.json --merge --deploy  # 以上 + 部署
```
默认不带 `--deploy`，步骤 8 放行后才加。质量不受影响：串联的全是确定性节点；语义节点仍由 AI/小爽把关。

> 💡 **任意子集都行**：`--candidates 候选.json` 只动候选里的 serial，交 1 家或 1773 家都成立，不存在「只能跑全库」的限制。

**不会卡住的保障**：
- 脚本报错 → 看报错修数据，重跑
- AI 拿不准 → 标记「待小爽定」，进步骤 8，**不阻塞其他企业**
- 子智能体超时/差 → 换 prompt 或自己做一遍再让它复查
- 小爽驳回 → 只修有问题部分，不从头来
- **单家不阻塞批量**（一批 20 家有 3 家争议，先推 17 家，3 家「待定」）

## 5. 每步骤详细规则

（这部分给你看，了解详细流程规则；不那么重要且占篇幅多的内容放附录里了）

### 5.1 步骤 1 · 银发相关性判断（两阶段）

**阶段一 · 初筛（强词脚本）**

`config.SILVER_STRONG_KEYWORDS`（76 个中英文强词），被 `selection/relevance_screener.py` 使用。命中 → 进阶段二；未命中 → 直接拒绝（除非特殊理由）。

> 完整 76 词清单见 **附录 C.1**。代码在 `config.py` 的 `SILVER_STRONG_KEYWORDS`。

**阶段二 · 低模判断（AI 是非题）**

符合任一即保留：
- 直接面向 **50 岁+或 60 岁+** 人群（C 端）
- 面向 **Medicare Advantage 参保老人（C 端）**
- 为上述人群的服务方提供产品 / 服务

**直接拒绝**：综合电商（养老仅「规划中」）、品牌 PR、Web3、泛再生医学、泛医疗 VC、泛融媒体。

> 关键词门禁是辅助，**最终以实质业务判断为准**；不确定联网核查，默认从严。

### 5.2 步骤 2 · 全库去重

**比对对象必须是全库 `all_enterprises.json`**

**粗筛**：`python scores_draft/rework/dedup_keyword_prescreen.py --name "企业名"` 或 `--candidates 候选.json`

原理：去括注 → 去公司后缀 → 去城市前缀 → 核心词提取 → 全库子串匹配 → 输出疑似重复。

**精确裁决**：

| 情形 | 处理 |
| --- | --- |
| 一致（信息无差异） | 跳过 |
| 增量（相似但信息有补充） | 合并进已有记录，补增量；拿不准标「待小爽定」 |
| 冲突（疑似同家但业务矛盾） | 联网复核，交小爽裁决 |

> ⚠️ 「乐龄圈」「康乐龄」「北京乐龄养老」= **3 家不同企业**（核心词同但主体不同）；「福寿康」+ 各地分公司 = **1 家**（合并进总部）。最终由 AI 校验，拿不准标「待小爽定」。

### 5.3 步骤 3 · 补全所有字段 + 前端展示（合并）

联网 / 翻译补齐所有在用字段。

- **必填最低门槛**：`serial` / `name` / `region` / `description(≥20字)` / `source` / `ingest_time` / `update_time`
- **补不到** → 标 **「待补充」**，**禁止编造**
- **`serial`**：格式 `#XXXX`，取现有最大值 +1
- **搜索索引** = `name`(+name_cn) + `description` + `tag_l1`/`tag_l2`（含同类词）+ `recommend`。（stage 不参与搜索索引但可前端展示）
- **引用网址记录**：补字段时把引用网址写入字段（website_url / crunchbase_url / source_urls 等）；月度入库后可跑 `python scripts/collect_source_urls.py` 统计高频站点 / 渠道去重。

**重点字段表（前端展示字段，有值才渲染，空值一律隐藏）**：

| 字段 | 展示位置 | 说明 |
| --- | --- | --- |
| name + name_cn | 卡片头部 | 中文名优先，英文名副 |
| tag_l2 | 头部标签栏 | 只展示二级标签（一级不展示） |
| total_score | 头部评分徽章 | 0~10 存储，前端 ×10 取整封顶 100；hover 显示四维（信号·信息·差异·复制） |
| description | 卡片主体 | 中文、≥20 字、说清「做什么 / 服务谁 / 怎么赚钱」；禁模板套话、禁英文主导、禁夹带原始标记（`check_description.py`） |
| recommend | 卡片主体 | 推荐理由：一段自然流畅的话，把信息量/差异化/可复制融进去讲，禁机械三段式（`check_single.py`） |
| funding_latest | meta 行 | 最新融资（需含数字才显示；金额 norm_amount 转 M→万、B→亿，币种保留） |
| funding_total | meta 行 | 累计融资（需含数字才显示；同上） |
| investors | meta 行 | 投资方 |
| payor_model | meta 行 | 支付模式（如"商业保险支付+个人自费"） |
| founded | meta 行 | 成立年份 |
| website_url / crunchbase_url | meta 行 | 外链 |
| 🔥 徽标 & 近期动态 / 报道 | 头部/底部 | 🔥 仅非媒体企业且 30 天内有被报道；媒体企业显示"近期报道" |
| deep_article_links | 卡片底部 | 深度文章链接（有值才显示，无则整块隐藏） |

> 字段补全完跑 `gen_enterprise.py` 生成，肉眼看卡片渲染是否正常。
> 完整字段字典（41 个）见 **附录 C.4**；**不再展示的字段、筛选器、排序规则**见 **附录 C.3**。

### 5.4 步骤 4+5 · 评分与推荐理由

**模型策略**（07-24 定）：所有 AI 判断统一用最便宜模型（当前 HY3 免费可用）。国内 / 海外来源同等重要，不因省钱过度牺牲质量。

**评分架构（四阶段）**：

1. **阶段 1–2**：银发相关性判断 / 准入（§5.1）
2. **阶段 3 · 信号强度**（`selection/signal_strength.py`，0~10，保底 0.5 封顶 10）：企业与资讯共用 `compute_signal_strength()`。企业评分时把该企业**最新融资/大事件**拼成 article dict 喂函数。
3. **阶段 4 · 四维精评**（最便宜模型）：输出 `recommend` + 四维评分（info / diff / copy）。

**公式**：`total_score = 信号×30% + 信息×30% + 差异×20% + 复制×20%`（每维 0~10，total 0~10，前端 ×10 显示封顶 100）。详细分级阈值见 **附录 C.2**。

> 🆕【新增 V8.5】**评分怎么跑（边界关键，澄清"能不能只跑指定名单"）**
> - **日常入库：只算候选里的企业，想交多少交多少。** AI 在生产候选阶段填好 `recommend` + 四维(`info_score`/`diff_score`/`copy_score`) + `funding_latest` 等写入候选.json，再跑 `python scripts/score_candidates.py --candidates 候选.json` 一键补 `signal_strength` + `total_score`（脚本算，零模型成本）。
> - **合并天然支持任意子集**：`enterprise_build.py --candidates 候选.json --merge` 只动候选里的 serial，交 1 家或 1773 家都行，**不存在"只能跑全库"的限制**。
> - **全库重跑是另一回事**：`merge_batch_scores.py` + `signal_strength.py` 仅用于「公式/权重变了，要重算全部 1773 家」这种罕见场景，**不在日常入库轮次对全库跑**。

**推荐理由写法**：一段自然流畅的话，把信息量/差异化/可复制融进去讲，不分段、不逐维列。禁止机械三段式——三维真判断由步骤 7 子智能体走查负责。

### 5.5 步骤 6 · 质量门禁（脚本）

门禁 = **规则校验脚本**，针对 `recommend` / `description` 两个字段。一次跑完：

- `check_description.py`：D1 description≥20字 / D2 中文>30% / D3 无BANNED模板 / D4 无原始标记残留
- `check_single.py`：R1 单字符串 / R2 20~200字 / R3 禁模板套话 / R4 禁出现企业名 / R-redundancy 禁复述列表字段 / R-noabs 禁绝对化 / R-jargon 禁黑话 / R-filler 禁填充 / R10 跨企业雷同(LCS≥15且Jaccard>0.5)

> 规则以脚本为唯一权威。R5 与 R-integrity 已于 V7.4 删除。门禁不过 → `enterprise_build.py` 直接终止，先修再合并。

### 5.6 步骤 7 · 子智能体走查（独立全库走查清单）

走查 ≠ 门禁。门禁是脚本规则校验（§5.5）；走查是**语义复核**，派 general-purpose 子智能体，按下面 6 项清单逐条看：

1. **description**：中文为主、说清做什么/服务谁/怎么赚钱、无模板套话、无英文主导、无原始标记残留
2. **recommend**：有真判断（信息量/差异化/可复制三方面）、不机械三段式、不复述 description 基本事实
3. **银发信号**：该企业保留是否确有银发实质（无银发信号应删，绝不进兜底桶）
4. **字段齐全性（所有在用字段覆盖率）**：逐字段看覆盖率，重点 `description`/`source`/`ingest_time`/`tag_l2`/`signal_strength`/`total_score`；空值过多标「待补充」而非编造
5. **标签**：`tag_l2` 是否在 `_l2_l1.json` 词表、是否 1~3 个、是否跨一级重复
6. **前端网站**：合并部署后从网站使用者角度走查（渲染/搜索/筛选/排序/🔥徽标），见 §5.9

> 💡 **description 和 recommend 走查是不是重复了？** 不重复。门禁(check_single/check_description)分别校验两者规则；本走查是语义复核，分两条是因为关注点不同——description 查「事实准不准」，recommend 查「判断好不好」。一条查事实，一条查观点，缺一不可。

循环：第一轮 → 你修复 → 第二轮（换 prompt 或同一重跑）→ 最多两轮 → 仍有问题标「待小爽定」。每轮之间由你负责修改，不让子智能体自己改。

### 5.7 步骤 8 · 小爽审核

发**全字段预览表**（自动生成：`python scripts/build_preview.py --candidates 候选.json --out 预览表.xlsx`）。银发信号判定 / 去重结果两列留空由你填。

**审核附言（必写，三部分）**：①遇到的问题 ②需要协助 ③建议。不写「无」。

**驳回处理**：个别误 → 改字段重跑门禁重提；多家共性问题 → 批量改重提；规则分歧 → 给判断+理由交小爽拍板。驳回 ≠ 从头来，只修有问题部分。

### 5.8 步骤 9 · 合并部署

首选一条命令：`python scripts/enterprise_build.py --candidates 候选.json --merge --deploy`

手动分步（等价，出问题时定位）：
1. 编辑 `all_enterprises.json`（合并 = 编辑真相源）
2. 跑 `gen_enterprise.py` 重生成 `output/`
3. `deploy_ghpages.py` 部署
4. `git commit` 留痕

### 5.9 步骤 10 · 上线走查（只走网站前端）

合并前后已在步骤 7 派子智能体走查覆盖**内容质量**（description/recommend/信号/字段/标签）。上线走查只从**网站使用者角度**看：

- 截图看卡片渲染、搜一家 / 筛一个标签 / 排个序是否正常、🔥 徽标与近期动态是否出现
- 抽看 1~2 页即可

**问题处理**：
- **小问题**（样式/渲染/错位等）→ AI 直接改 + 重部署，**不回滚、不通知小爽**
- **规则 / 数据实质问题** → 回滚并交小爽拍板

> 严禁现场手改线上；任何改动走代码 → 重生成 → 重部署。

### 5.10 步骤 11 · 收尾（扁平 6 步）

做完一批企业后，按顺序执行：

**1. 写 memory（两份）**

> ```markdown
> - 每日工作日志 `.workbuddy/memory/YYYY-MM-DD.md`：记「本轮做了什么」（append-only）
> - 项目长期记忆 `.workbuddy/memory/MEMORY.md`：只记跨轮不变的长期事实（版本号/铁律/约定）；版本升了同步更新版本号
> - 两者都在 `silver-pulse/.workbuddy/memory/` 目录，**不进 git**
> ```

**2. git 提交留痕**：所有改动 commit（不一定要 push）。

**3. 归档清理（月度）**：每月检查 `_deprecated/` 下 1 个月前的临时文件 → 删或续归档；根目录散落脚本移 `_deprecated/`。

**4. 升版本（仅当规则/流程/字段表发生变化时才做，不变则跳过）**

> 📌 **标记约定（每次改文档必守）**：任何改动哪怕一字，都用引用块标注 🆕【新增】/ ✂️【删除】/ ✏️【调整】并写原因；正文保持纯净不带符号；下版整体删除这些解释块。
>
> 📌 **文档代码一致性（改代码或改文档都执行）**：改了代码（门禁/评分/字段/脚本）→ 同步查手册对应节；改了手册（规则/流程/字段表）→ 同步查代码实现；两者同一次 commit。不一致以「经判断的最新正确版本」为准（代码也可能错）。

```
升版本动作（8 步）：
1. 判版本号：功能变更 → 大版本+1；修正优化 → 小版本+0.1；纯错字不升
2. 顶部写变更对照表：只列本版相对上版的变动，每条标 🆕/✂️/✏️
3. 正文标改动：每个调整处紧跟一个引用块说明原因；同时删掉上一版的所有解释块
4. 与上一版逐节比对：上版有的本版保留或显式说明为何移除
5. 版本沿革（附录 E）补一行
6. 旧版移入 `_archive_企业库旧文档/`；运维目录只留最新版 + 任务规划 + 行为准则
7. 更新 MEMORY.md 的当前版本号
8. git 提交（与代码改动同一次 commit）
```

**5. 自检项（汇报前快速勾过）**

> ```markdown
> - [ ] 标记完整性：所有改动都有 🆕/✂️/✏️ 引用块，正文纯净零符号
> - [ ] 对照表准确性：顶部对照表列出了本版全部变动，无遗漏
> - [ ] 字段/门禁/前端表：与上一版逐项核对，无遗漏无多余
> - [ ] config.py 同步：强词清单等双写位置（代码+手册）一致
> - [ ] memory 双份：日志 + 长期记忆都已更新
> ```

**6. 汇报小爽**

```
① 需拍板/协作的点
② 我的下一步计划
③ 我的建议/想法 + 本次复盘（解决了什么 / 为什么发生 / 怎么避免再发生 / 落在哪一层）
```

> 复盘规范见《企业库行为准则》最新版（`企业库运维/企业库行为准则.md`）。

### C.2 四维评分详规（详细分级阈值）

综合评分 = 信号强度×30% + 信息量×30% + 差异化×20% + 可复制×20%
前端展示数值，四个维度分别 ×10。

**1、信号强度（0~10 分）**
各项相加，封顶 10 分（保底 0.5），`selection/signal_strength.py`：
- 信源起点：T1=0.5，T2=0.3，T3=0.1（阶段2 已预筛过银发相关性，信源等级只作微弱起点）。
- IPO = +6。
- 融资（海外美元，≥）：10 亿=5，1 亿=4，5000 万=3，1000 万=2，500 万=1，100 万=0.5，其余=0。
- 融资（国内元，≥）：10 亿=6，1 亿=5，5000 万=4，1000 万=3，500 万=2，100 万=1，50 万=0.5，其余=0。
- 收购（海外美元 / 国内元，≥）：100 亿=6，50 亿=5，10 亿=4，1 亿=3，5000 万=2，1000 万=1。
- 时效（每月重算）：近 1 周=2.5，近 1 月=2，近 2 月=1.5，近半年=1，近 1 年=0.5，更久=0.25。

**2、信息量（0~10）**：搜这家企业 / 事件前几页信息的数量和质量（信息越多越好写，通常是大企业 / 热点）。

**3、差异化（0~10）**：商业模式反不反常识、企业起落是否反复巨大。

**4、可复制（0~10）**：基于企业库 + 可联网搜网上信息，判断国内有无同类赛道、赛道里有没有上亿融资 / 上市公司、支付方差异（美国 Medicare / 自费 vs 中国医保 / 自费，日本近似中国）→ 能不能平移、是空白还是红海。
