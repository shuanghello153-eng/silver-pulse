## 1. 网站定位

Silver Pulse（银脉）= 银发经济投融资资讯聚合 **+ 企业数据库**，本质是小爽的"选题情报台"——让小爽一眼看到"今天哪些企业 / 资讯值得写深度稿"。

每家企业 / 每条资讯的终点问题都是：中国银发经济创业者能从中借鉴什么？

---

## 2. 基本情况

- **唯一真相源**：`data/enterprise/all_enterprises.json` —— 直接改它 = 改真相。当前约 **1773 家**、43 字段。
- **部署**：独立 `gh-pages` 分支（main 放代码/数据，gh-pages 只放生成的网页）。LIVE：`https://shuanghello153-eng.github.io/silver-pulse/`
- **采集**：由**信源扩充 AI** 负责（RSS-first，44 信源，海外为主）。企业库不碰采集。

---

## 3. 个人职责

**你是企业库的唯一维护者，** 数据入库 + 前端渲染 + 部署 + 文档与记忆等，全部由你负责，**所有字段你都要维护**（只读 / 废弃字段除外，见附录 C）。

**小爽**：定方向、做最终审核与发布放行。你**不擅自入库、不擅自部署**；改小爽手标内容必须【动你标注】+ 显式理由交他拍板。

**信源扩充 AI**：全网搜集资讯渠道和企业名单，提交给资讯 AI、企业库 AI（=你）

**资讯 AI**：资讯一切维护（含入库、评分、推荐理由、前端渲染、部署、文档与记忆等）

**标签 AI**：负责标签体系 `tag_l1`、`tag_l2` 构建

## 4. 整体工作流程

所有任务走**同一套流程**，只是「从哪进、走到哪停」不同。不存在多套独立流程。

### 4.1 需求来源

| 来源 | 走哪条流程 | 说明 |
|---|---|---|
| **A. 小爽给企业名单** | → 完整 1→8 步 | 最常见 |
| **B. 每周资讯扫描发现企业名单** | → 完整 1→8 步 | 每周日 23:00 自动化扫描，附录 B |
| **C. 外部 AI 给企业名单** | → 完整 1→8 步 | 附录 A、附录 B |
| **D. 存量走查发现问题** | → 从步骤 3 起（准入/去重已做过） | 纯 UI/UX 小改动可走「直接改 → 直接部署 → 事后补审」，不必走完整审核关卡 |

- 目前大部分任务都记录在《企业库任务规划_V\*.md》（最新版本 V\*），可自行领取。

### 4.2 入库主流程

简述基本流程规则，并列出每步 AI 要执行的代码与数据流向——AI 看这一节就能跑通整个入库。（「代码」列 = 这一步用哪个脚本；「输入 → 输出」列 = 这一步吃进什么、产出什么、产出交给哪一步。）

| # | 步骤 | 类型 | 代码 | 输入 → 输出 |
|---|------|------|------|------------|
| 1 | **银发相关性判断**（入库准入） | 脚本初筛 + AI 二筛 | `selection/relevance_screener.py` | 企业名单 → 命中强词者进 AI 是非题 → 通过者进候选 |
| 2 | **全库去重** | 脚本粗筛 + AI 裁决 | `scores_draft/rework/dedup_keyword_prescreen.py` | 候选名单 vs 全库 → 疑似重复 AI 裁决 → 确认的新企业留下 |
| 3 | **补全所有字段**（含写 recommend、算评分、门禁自测） | AI 为主 + 脚本 | `scripts/score_candidates.py`、`check_single.py`、`check_description.py` | 联网/翻译补字段 + AI 写 recommend + AI 填三维评分 → score_candidates.py 补信号强度/总分 → 两个门禁脚本自测通过 → 候选.json 字段齐全 |
| 4 | **子智能体走查** | AI 走查 | —（派 general-purpose 子智能体） | 读候选.json 语义走查（≤2轮）→ 问题由你修复 → 定稿 |
| 5 | **小爽审核** | **人工卡点** | `scripts/build_preview.py` | 候选.json → 全字段预览表.xlsx + 审核附言 → 放行 / 驳回 |
| 6 | **合并部署** | 脚本 | `scripts/enterprise_build.py` | 候选.json → 门禁→备份→合并进 all_enterprises.json →生成 output/ → `--deploy` 上线 |
| 7 | **上线走查** | AI + 人眼 | 线上页面（gen_enterprise.py 产物） | 线上抽查 5 家卡片 + 搜索/筛选/排序 → 小问题直接改 + 重新部署 |
| 8 | **收尾** | AI | — | 任务规划 / 升版本(如需) / memory / git / 归档 / 自检 / 汇报 |

```
贯穿全程的工作产物 = 候选 JSON（候选.json）
├─ 步骤 1–5 产出的新企业数据先写进候选 JSON
├─ 门禁 / 走查 / 预览 全部读它
├─ 步骤 6 才合并进真相源(all_enterprises.json)
└─ 评分/门禁默认对候选.json跑，绝不在合并前改全库
```

评分与合并都对**任意名单**生效：候选.json 里放 1 家还是 1773 家都行，`score_candidates.py` 和 `enterprise_build.py --candidates` 都只动名单内的企业。

### 4.3 防卡住五原则

> ✏️【调整 V8.6】原本节还列了 enterprise_build 三条命令，与 §5.6 完全重复；命令统一收进 §5.6，本节只留原则。

- 脚本报错 → 看报错修数据，重跑

## 5. 每步骤详细规则

本节给小爽看——详细流程规则；不那么重要且占篇幅多的内容放在文末附录。（§4.2 主流程表是给 AI 看的执行入口，两者一一对应。）

### 5.1 步骤 1 · 银发相关性判断（两阶段）

**阶段一 · 初筛（强词脚本）**

`config.SILVER_STRONG_KEYWORDS`（76 个中英文强词），被 `selection/relevance_screener.py` 使用。命中 → 进阶段二；未命中 → 直接拒绝（除非特殊理由）。

> 完整 76 词清单见 **附录 C.1**。代码在 `config.py:2696` 的 `SILVER_STRONG_KEYWORDS`。

**阶段二 · 低模判断（AI 是非题）**

符合任一即保留：

- 直接面向 **50 岁+或 60 岁+** 人群（C 端）
- 面向 **Medicare Advantage 参保老人（C 端）**
- 为上述人群的服务方提供产品 / 服务

**直接拒绝**：综合电商（养老仅「规划中」）、品牌 PR、Web3、泛再生医学、泛医疗 VC、泛融媒体。

> 关键词门禁是辅助，**最终以实质业务判断为准**；不确定联网核查，默认从严。

### 5.2 步骤 2 · 全库去重

**比对对象必须是全库 `all_enterprises.json`**

**粗筛**：`python scores_draft/rework/dedup_keyword_prescreen.py --name "企业名"` 或 `--candidates 候选.json`

原理：去括注 → 去公司后缀 → 去城市前缀 → 核心词提取 → 全库子串匹配 → 输出疑似重复。

**精确裁决**：

| 情形 | 处理 |
|---|---|
| 一致（信息无差异） | 跳过 |
| 增量（相似但信息有补充） | 合并进已有记录，补增量；拿不准标「待小爽定」 |
| 冲突（疑似同家但业务矛盾） | 联网复核，或交小爽裁决 |

### 5.3 步骤 3 · 补全所有字段（含推荐理由 / 评分 / 门禁自测）

联网 / 翻译补齐附录 C 里所有在用字段，**补不到** → 标 **「待补充」**，**禁止编造**。

**必填最低门槛**：`serial` / `name` / `region` / `description(≥20字)` / `source` / `ingest_time` / `update_time`

**重要字段表（含 13 个前端展示字段，有值才渲染，空值一律隐藏）**：

| 字段 | 展示位置 | 说明 |
|---|---|---|
| name + name_cn | 卡片头部 | 中文名优先，英文名副 |
| tag_l2 | 头部标签栏 | 只展示二级标签（一级不展示）；从 `data/enterprise/_l2_l1.json` 现有体系选 1~3，不自造新词 |
| total_score | 头部评分徽章 | **0~10 分制存储，前端 ×10 取整封顶 100**；hover 显示四维（信号·信息·差异·复制）。`total_score = 信号强度×30% + 信息×30% + 差异×20% + 复制×20%`，怎么算见下方「评分」 |
| description | 卡片主体 | 介绍：中文、≥20 字、说清「做什么 / 服务谁 / 怎么赚钱」（事实）；禁模板套话、禁英文主导、禁原始标记残留。门禁 `check_description.py` |
| recommend | 卡片主体 | 推荐理由：一段自然流畅的话，把信息量 / 差异化 / 可复制融进去讲，禁止机械三段式、重复列表。讲「为什么值得写」（判断）。门禁 `check_single.py` |
| funding_latest | meta 行 | 最新融资（需含数字才显示；金额 `norm_amount` 转换 M→万、B→亿，币种符号保留） |
| funding_total | meta 行 | 累计融资（需含数字才显示；同上） |
| investors | meta 行 | 投资方 |
| payor_model | meta 行 | 支付模式（如"商业保险支付+个人自费"），有值才显示 |
| founded | meta 行 | 成立年份 |
| website_url / crunchbase_url | meta 行 | 外链 |
| 🔥 徽标 | 头部 | "近期有动态"（仅非媒体企业、且 30 天内有被报道） |
| 近期动态/报道 | 卡片底部 | 关联新闻列表（媒体企业显示"近期报道"） |
| deep_article_links | 卡片底部 | 深度文章链接（有值才显示，样式类似近期动态报道，放在卡片最后一排；无则整块隐藏） |

**评分（写进候选.json 的 5 个数：signal_strength / info / diff / copy / total）**：

1. AI 按附录 C.1.1 的规则给 **信息量 / 差异化 / 可复制** 三维打分（最便宜模型）
2. 跑 `python scripts/score_candidates.py --candidates 候选.json` → 自动补 **signal_strength + total_score**（交几家算几家，任意名单）

> `merge_batch_scores.py` + `selection/signal_strength.py` 是**全库重跑**工具（公式/权重变了才重算全部 1773 家），日常入库轮不碰它们。

**搜索索引**（按 `gen_enterprise.py` 实际实现）= `name` + `description` + `tag_l1` + `tag_l2` + `business_model` + `business_tags` + `stage` + `recommend` + `highlights`。

> ✏️【调整 V8.6】原手册写「name(+name_cn)…stage 不参与搜索索引」——查代码后两处都不对：stage、highlights 实际**参与**搜索，name_cn 实际**不参与**。手册以代码实际行为为准改正。name_cn 要不要加进搜索是个待拍板改进项（见汇报）。

**引用网址记录**：补字段时把引用网址写入字段（website_url / crunchbase_url / source_urls 等）；月度入库后可跑 `python scripts/collect_source_urls.py` 统计高频站点 / 渠道去重，输出至 `handoff/news_inbox/`。

**门禁自测（本步收尾一次跑完；专门针对 description / recommend 两个字段的脚本）**：

- `check_description.py`：D1 ≥20字 / D2 中文>30% / D3 无 BANNED 模板 / D4 无原始标记残留
- `check_single.py`：R1 单字符串 / R2 20~200字 / R3 禁模板套话 / R4 禁企业名 / R-redundancy 禁复述列表字段 / R-noabs 禁绝对化 / R-jargon 禁黑话 / R-filler 禁填充 / R10 跨企业雷同

规则以脚本为唯一权威（R5 与 R-integrity 已于 V7.4 删除）。

### 5.4 步骤 4 · 子智能体走查（≤2 轮）

**批次走查（每批入库必做）**——派 general-purpose 子智能体，指令要点：

1. description 是否中文为主、说清做什么/服务谁/怎么赚钱、无模板套话
2. recommend 是否有真判断（信息量/差异化/可复制三方面）、不复述 description 基本事实
3. 两者是否重复（不重复：description 查事实准不准，recommend 查判断好不好）
4. 银发信号判定是否合理
5. 字段齐全（尤其 description / source / ingest_time）
6. 标签是否在 `_l2_l1.json` 词表中

循环：第一轮 → 你修复 → 第二轮（换 prompt 或同一个重跑）→ 最多两轮 → 仍有问题标「待小爽定」。每轮之间由你负责修改，不让子智能体自己改。

走查后**自己审一遍**：打开预览表逐行看，确认走查问题修好、无漏网。

**全库走查（定期，不随批次，在任务规划里排期）**，共 7 项：

① description / recommend 质量抽查 ② 银发信号复核（无信号即删，不进兜底桶） ③ 字段覆盖率（**所有在用字段**统计空值率，不只必填字段） ④ 标签合法性（`validate_tags.py` 9 项） ⑤ 评分分布异常（缺分/全 0/离群值） ⑥ 疑似重复企业 ⑦ 前端网站（渲染/搜索/筛选/排序，每次前端调整后必查）

### 5.5 步骤 5 · 小爽审核

发**全字段预览表**（自动生成：`python scripts/build_preview.py --candidates 候选.json --out 预览表.xlsx`）。银发信号判定 / 去重结果两列留空由你填。

**审核附言（必写，三部分）**：①遇到的问题 ②需要协助 ③建议。不写「无」。

**驳回处理**：个别误 → 改字段重跑门禁重提；多家共性问题 → 批量改重提；规则分歧 → 给判断+理由交小爽拍板。驳回 ≠ 从头来，只修有问题部分。

### 5.6 步骤 6 · 合并部署

**编排脚本** `scripts/enterprise_build.py`，一条命令走完（默认不带 `--deploy`，步骤 5 放行后才加）：

```
python scripts/enterprise_build.py --candidates 候选.json            # 门禁自测（不合并）
python scripts/enterprise_build.py --candidates 候选.json --merge    # 门禁→备份→增量合并→生成
python scripts/enterprise_build.py --candidates 候选.json --merge --deploy  # 以上 + 部署
```

手动分步（等价，出问题时定位）：

1. 编辑 `all_enterprises.json`（合并 = 编辑真相源）
2. 跑 `gen_enterprise.py` 重生成 `output/`
3. `deploy_ghpages.py` 部署
4. `git commit` 留痕

### 5.7 步骤 7 · 上线走查

只从**网站角度**走查（数据内容在步骤 4 已查过，不重复）：

- 打开线上页面截图，抽查至少 5 家卡片：介绍 / 评分 / 融资等渲染是否正常
- 测搜索、筛选、排序功能是否正常
- **发现小问题直接改 + 重新部署，不回滚、不通知小爽**；只有规则或数据实质错误才停下来报告

### 5.8 步骤 8 · 收尾

做完一批企业后，按顺序执行：

**1. 更新任务规划**：打开 `企业库任务规划_V*.md`，完成移「已完成」、新增登「进行中」、遗留登「待办」。

**2. 检查规则是否变了** → 变了走第 3 步升版本（含四问复盘）；没变跳过第 3 步。

**3. 升版本动作（8 小步，含标记约定与文档代码一致性）**：

1. 判版本号：功能变更 → 大版本+1；修正优化 → 小版本+0.1；纯错字不升
2. 顶部写变更对照表：只列本版相对上版的变动，变更写在表里，不另加解释文字
3. 正文标改动：每个调整处紧跟引用块，用 🆕【新增】/ ✂️【删除】/ ✏️【调整】写原因；正文保持纯净零符号；下一版整体删除这些解释块
4. 与上一版逐节比对：上版有的本版保留或显式说明为何移除
5. 文档代码一致性：改了代码（门禁/评分/字段/脚本）→ 同步查手册对应节；改了手册 → 同步查代码实现；两者同一次 commit；不一致以「经判断的最新正确版本」为准（代码也可能错）
6. 版本沿革（附录 D）补一行
7. 旧版移入 `_archive_企业库旧文档/`；运维目录只留最新版 + 任务规划 + 行为准则
8. 更新 MEMORY.md 的当前版本号

### C.1.1 四维评分详细规则

综合评分 = 信号强度×30% + 信息量×30% + 差异化×20% + 可复制×20%

前端展示数值 = 各维度 ×10。

**1、信号强度（0~10 分）**
各项相加，封顶 10 分（`selection/signal_strength.py`）：
- 信源起点：T1=0.5，T2=0.3，T3=0.1（阶段2 已预筛过银发相关性，信源等级没那么重要，只作微弱起点）
- IPO = +6
- 融资（海外美元，≥）：10 亿=5，1 亿=4，5000 万=3，1000 万=2，500 万=1，100 万=0.5，其余=0
- 融资（国内元，≥）：10 亿=6，1 亿=5，5000 万=4，1000 万=3，500 万=2，100 万=1，50 万=0.5，其余=0
- 收购（海外美元 / 国内元，≥）：100 亿=6，50 亿=5，10 亿=4，1 亿=3，5000 万=2，1000 万=1
- 时效（每月重算）：近 1 周=2.5，近 1 月=2，近 2 月=1.5，近半年=1，近 1 年=0.5，更久=0.25

**2、信息量（0~10）**

搜这家企业 / 事件前几页信息的数量和质量（信息越多越好写，通常是大企业 / 热点）。

**3、差异化（0~10）**

商业模式反不反常识、企业起落是否反复巨大。

**4、可复制（0~10）**

基于企业库 + 可联网搜网上信息，判断国内有无同类赛道、赛道里有没有上亿融资 / 上市公司、支付方差异（美国 Medicare / 自费 vs 中国医保 / 自费，日本近似中国）→ 能不能平移、是空白还是红海。
