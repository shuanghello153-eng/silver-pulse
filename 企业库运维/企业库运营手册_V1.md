## §2 读者背景（校验的最高原则，用来根本避免问题）

- **最终读者** = 小爽（国内银发财经作者，产品感强，非英文母语）+ 潜在国内银发创业者（国内小白，**多数不懂英文**、要"能直接借鉴"的启发）。
- **由此推出的最高原则**：企业介绍必须中文；**出现大段英文 = 质量事故**；要突出"国内可比性/可借鉴性"。
- **为什么这是"原则"不是"补洞"**：过去反复出现"英文漏翻""模板套话"，本质是校验只查长度、只盯具体规则，没从读者视角前置判断。所以——**派独立走查子智能体时，必须把"读者 = 国内小白、不懂英文"作为背景喂给它**，让它自带这双眼睛去判，而不是等我点名"英文要翻"。这是从根上降问题的机制，不是再加一条规则。

## §4 找企业（0→1 入门）

**企业从哪来（四类入口）**：
1. **资讯库月度关联**：每月跑 `rebuild_association.py`，扫当月资讯提取库外企业 → 进 §5 入库流程。
2. **信源治理遍历**：研究员按周轮转（W2 文娱 / W3 AIGC / W4 欧洲 …）发现线索，交我入库（见 `信源治理_全球遍历方案_V2.2.md`）。
3. **小爽/外部直接给名单**（如"这 100 家入库"）。
4. **历史专项批次**：那本书 / 选题库 V4 / 许之一 mapping 等。

**徒弟入门动作**：① 读 `PROJECT_STATUS.md`（现状）→ ② 看 `all_enterprises.json` 字段样例（理解"合格企业长啥样"）→ ③ 读 §3 规则 → ④ 从资讯月度关联练手。

## §5 入库动作（完整闭环，含前端与排序）

步骤：
1. **准入**：过银发信号铁律，无信号直接删。
2. **去重（对全库）**：已存在 → 合并；新记录必须带 `description`(>20字) 否则拦截。
3. **联网补字段**：`description` 中文主字段 + 融资/成立年/国内竞品/官网；查不到标"待补充"，**不编**。
4. **写 recommend**：按 `WORKER_PROMPT_V4` 思路 + 过 `check_single.py` 门禁。
5. **算评分**：仅新企业算 `signal_strength` / `research_value`；已有绝不重算。
6. **草稿隔离 → 自测**：本地改 `all_enterprises.json` 前先备份/分支；跑 check_single + 轻量描述检查。
7. **全字段预览发小爽审**：CSV/表发**全部字段**，不砍字段（表格小爽自己看，宽就拆多张）。
8. **放行才写回** → 重跑生成器三连（`gen_enterprise.py` + `gen_about.py` + `generator.py`）→ 部署（经小爽）。

**前端呈现对接**：`description` → 卡片介绍；`recommend` → 💡 推荐理由；`total_score` → 徽标；`tag_l2` → 筛选药丸。新增字段要展示，须在 `gen_enterprise.py` + `enterprise.html` 同步改。
**排序对接**：新企业若有动态，须在 `last_news_map` 四来源之一有日期，否则落"无动态组"按 `research_value` 排。

## §6 校验与迭代（含独立走查子智能体）

- 每次入库/批量改动后：跑 `check_single.py`（recommend 门禁）+ 轻量脚本查 `description` 非英文主导（带 Medicare/FDA 等白名单）/非模板/≥20字（基于 §2 读者背景原则，不是另造 8 条规则）。
