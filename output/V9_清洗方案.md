## 二、三类系统性根因

1. **通用占位/模板描述误导关键词标注（最致命，约 50+ 家）**
   - 模板 A：「康复辅具或适老化设备品牌，为老年人和行动不便人群提供辅助产品。」——套在 瑞尔齿科/美呀植牙/通策医疗/鼎植口腔（实为口腔诊所）、维达（纸品）、联谛信息 等身上 → 误打 医疗器械/康复设备。
   - 模板 B：「银发经济领域行业服务商，为养老产业提供相关产品。」——套在 摩登银龄/时尚奶奶团/银发无忧/彭世/硅基仿生 等 → 误打 智慧养老/适老化改造/智能硬件。
   - 模板 C：「健康养生品牌…养生保健」——套在多家消费品 → 误打 智慧养老。
   - **后果**：描述本身无真实业务信号，关键词标注必然不准。

2. **伞词兜底（大标签当垃圾桶）**
   - 智慧养老(139)、投资机构(62)、保险(33)、养老社区(68)、养老机构(26)、社交平台(44) 均混入大量非匹配成员（软件商/REIT/搜索平台/咨询/陪伴机器人/概念词条）。

3. **非企业「概念词条」混入企业库**
   - 联邦医疗保险优势计划、银行＆保险公司、行业服务 等是「类别/概念」，不是企业实体，却作为企业被打标。

## 三、建议分三期执行（对齐你「该拆就拆、别合并」的原则）

### Phase 0 — 数据质量地基（最优先，否则后续白做）
- 定位所有命中「模板 A/B/C」描述的企业（约 50+ 家），**回填真实业务描述**（来自公开资料/你手上的选题库）。
- 无真实描述者先挂「待核实」兜底，不盲目打标。
- 删除 3 个非企业概念词条（联邦医疗保险优势计划 / 银行＆保险公司 / 行业服务）。

### Phase 1 — 高置信错标批量纠正（~116 处，低争议）
从三组报告中抽取「描述与标签语义直接矛盾」的项，建 `V9_FIX` 覆盖表逐家锚定，例如：
- 药房（Alto Pharmacy / Capsule / PillPack）→ 用药管理
- 口腔诊所（瑞尔/美呀/通策/鼎植）→ 诊所
- 维达（纸品）→ 移出
- 豪悦护理（成人失禁）→ 尿失禁
- 听力训练 APP（Lace AI Pro / Rylo / TympaHealth / eargym）→ 数字健康
-  insurers 误归投资机构（Humana/Aetna/UHG/Cigna）→ 保险
- 运营企业误归投资机构（Aveanna/Enhabit/Essity/Ready Responders）→ 对应运营标签
- 护理/平台 误归保险（Author Health/CareMax/Grow Therapy/Headway/Nourish…）→ 医疗/数字健康

### Phase 2 — 伞词拆分（你「该拆就拆」原则的直接落地）
- **智慧养老(139)** → 拆出 `养老信息化平台`(~30) + `居家医疗`(~25，与上门医疗合并) + `安全监测硬件`(~10) + `护工/家属支持`(~8)；余下噪声剥离。
- **投资机构(62)** → 保留 REIT/VC/PE；运营/产品/媒体公司迁出。
- **保险(33)** → 仅留真保险人；护理/平台迁出；概念词条删。
- **养老社区(68) / 养老机构(26)** → 迁出软件商/REIT/搜索平台/咨询/AARP/书店；认知症数字疗法平台迁 认知症。
- **社交平台(44)** → 迁出医疗/照护机构、机器人厂商、软件商。

### Phase 3 — 校验与交付
- 每期跑 `validate_tags.py` 保 9/9；重建全映射 v9 文档 + xlsx。
- 同名/幽灵/碰撞自检。
