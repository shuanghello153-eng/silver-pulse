# 一、评分规则（四阶段）

资讯和企业走同一套。阶段 1–3 是脚本（0 成本），阶段 4 用强模型（0722 前免费）。

## 阶段1 初筛（脚本）✅ 已落地
1. ⚡️ 强词命中 **或** 命中已知企业库（`all_enterprises.json`）→ 准入；其余不准入。
2. ⚡️ 已删除弱词、已删除反向词（反向词会误杀"老幼共居""年轻人给老人提供服务"等真银发场景；模糊判断交阶段2）。
3. 去重：标题归一化 + URL 哈希，2 周窗口内重复文章不再进入。
4. 抽查检验：每次跑完自动抽样，报告每条命中的强词 / 已知企业，写 `data/run_logs/relevance_audit_*.json`（只读）。
5. 强词清单（`SILVER_STRONG_KEYWORDS`，约 60 个）：
   养老 / 老年 / 老人 / 银发 / 长者 / 长辈 / 退休 / 适老 / 适老化 / 照护 / 康养 / 医养 / 助老 / 陪护 / 康护 / 颐养 / 老年病 / 长寿 / 居家护理 / 居家照护 / 康复 / 慢病 / 认知症 / 痴呆 / 阿尔茨海默 / 失智 / 失能 / 护理院 / 养老院 / 敬老院 / 养老社区 / 养老产业 / 银发经济 / 养老金融 / 养老科技；英文 aging / elderly / senior / senior care / elder care / aged care / dementia / alzheimer / long-term care / nursing home / assisted living / home care / caregiver / caregiving / hospice / medicare / medicaid / retirement / senior living / pace program / value-based care / older adult / silver economy / age tech / memory care / senior housing。

## 阶段2 低模二筛（便宜 AI，约 ¥0.001–0.003/条）✅ 功能已落地，默认关、先不跑数据
判断标准——符合任一即相关：
- ① 直接面向老年人群（C 端），或面向 Medicare / Medicare Advantage 用户，提供产品或服务；
- ② 为【服务上述人群的 B 端企业】提供产品 / 服务的上游供应商或服务商（B2B，如给养老机构、Medicare Advantage 计划提供软件 / 设备 / 服务）。
- 泛医疗、泛健康、一般医院并购、儿科 / 孕产、面向年轻人或儿童的产品，即使带"养老""健康"等词，也不算。

1. 是非题：相关 → 放行；不相关 → 踢出并写 `data/blocked_log.json`（标题 + 来源 + 原因 + 时间，原始数据不删，随时可回捞）。
2. 自动抽查：跑完抽查前 20 条被拦项，若被拦项命中已知银发企业 → 打印 WARN 疑似误杀。
3. 模型：0722 前用 HY3（免费）；0722 后用 DeepSeek V3.2（硅基流动，OpenAI 兼容接口）。

## 阶段3 信号强度（脚本，0~10 分）✅ 已落地
各项相加，封顶 10 分（`selection/signal_strength.py`）：
1. 信源起点：T1=0.5，T2=0.3，T3=0.1（阶段2 已预筛过银发相关性，信源等级没那么重要，只作微弱起点）。
2. IPO = +6。
3. 融资（海外美元，≥）：10 亿=5，1 亿=4，5000 万=3，1000 万=2，500 万=1，100 万=0.5，其余=0。
4. 融资（国内元，≥）：10 亿=6，1 亿=5，5000 万=4，1000 万=3，500 万=2，100 万=1，50 万=0.5，其余=0。
5. 收购（海外美元 / 国内元，≥）：100 亿=6，50 亿=5，10 亿=4，1 亿=3，5000 万=2，1000 万=1。
6. 时效（每月重算）：近 1 周=2.5，近 1 月=2，近 2 月=1.5，近半年=1，近 1 年=0.5，更久=0.25。
7. 喂 AI 门槛：0722 前全部喂；0722 后只喂 ≥5 分的。

## 阶段4 强模精评（强 AI，免费期零成本）❌ 待建
AI 一次通读企业 / 资讯全部资料，同时完成以下几件事：
1. 信息量（0~10）：搜这家企业 / 事件前几页信息的数量和质量（信息越多越好写，通常是大企业 / 热点）。
2. 差异化（0~10）：商业模式反不反常识、企业起落是否反复巨大。
3. 可复制（0~10）：基于企业库 + 可联网搜网上信息，判断国内有无同类赛道、赛道里有没有上亿融资 / 上市公司、支付方差异（美国 Medicare / 自费 vs 中国医保 / 自费，日本近似中国）→ 能不能平移、是空白还是红海。
4. 综合评分 = 信号强度×30% + 信息量×30% + 差异化×20% + 可复制×20%（是这个公式算出的结果，不是另外再打一个分）。
5. 输出评分依据（就是推荐理由，两者是一回事）：用一段自然、流畅的话，说清这条为什么值得写、能从中国什么角度切入，把信号强度、信息量、差异化、可复制四方面的判断融进去讲，不刻意分段、不逐维列分。写完后自检一遍：凡是企业卡片 / 列表已展示的结构化信息（融资金额、轮次、标题、摘要、来源、日期等），评分依据里不再重复陈述；若某条这类信息对判断确实关键，可作为论据点到为止，但以不与列表重复展示为准。

# 三、前置工作：打标签方案

打标签（含 business_tags）是评分前唯一要提前做的准备——它决定"可复制"维度里国内赛道判断准不准。

## 1. 现状
一级标签 12 个、二级标签 58 个、0 幽灵标签（<3 家），结构本身干净。真正的隐患是"兜底桶"——把拿不准的企业一股脑塞进某个大标签。最严重的是「保健品」：89 家里混进了 Oak Street Health、Iora Health（美国 Medicare 诊所）、LHC Group（居家医疗）、DiningRD / Foodsmart（营养餐）等明显不是保健品的企业。这就是"分类看着乱"的真实来源，也是这次要重点清的。

## 2. 三层结构（怎么管）
- 一级标签（12 个）：分组容器，前台按它分组。
- 二级标签（58 个）：最小颗粒的可搜词，前台可点筛选；一个企业最多挂 5 个。
- 同类词（别名）：只用于搜索命中，不展示、不单列成标签（例：搜"老花镜"命中"眼镜"）。
- 真相源：`_rebuild_tags.py`（改这里的映射 / BRAND_OVERRIDE / MISLABEL_FIX），跑完用 `validate_tags.py` 校验，9 项全绿才算过关。绝不手改单条数据后不校验。

## 3. 打标规则（好标签硬标准）
1. 最小颗粒度：二级标签是能直接搜、有区分度的具体词（认知症 / 助听器 / 老年鞋），不是大伞词。
2. 一级 ≠ 二级：容器名和具体词不能同名。
3. 不与列表字段重复：融资状态 / 被收购 / 地区 / 成立年这些卡片已显示的，不做成标签。
4. 同义词并成一个规范标签，别名进同类词层。
5. 每个二级标签 ≥ 3 家；每个企业标签 ≤ 5 个。
6. 用受控词表，不自造新词。

## 4. 阶段4 AI 通读时怎么打标（工作流 + 不一致怎么办）
AI 读完一家企业全部资料后：
1. 从现有 58 个二级标签里选能对上的（≤5 个），能用现成的就用现成的。
2. 若企业明显不属于任何现有标签 → 不自己造词，写进「候选新标签」清单（企业名 + 建议词 + 理由），交小爽拍板后再由 `_rebuild_tags.py` 落地。
3. 若判断某个现有标签打错了（如保健品桶里的 Oak Street Health）→ 不静默改，标成【动你标注】+ 理由，小爽确认后再落。
4. 一句话原则：AI 只能"提议"，小爽"拍板"；新词不自造、错标不静默改、每次改完必重跑校验 9 项 + 交付完整大表（含每个二级标签的全部同类词，不省略）。

## 5. 本轮要清的桶（具体任务）
1. 「保健品」89 家逐家重判：真保健品 / 处方药·中药（拆入新增"处方药"二级标签）/ 医疗服务（Oak Street · Iora · LHC 类，归医疗健康相应标签）/ 营养餐（并入营养食品）。
2. 其余 >80 家的大桶（智能硬件 173、居家护理 160、老年文娱 150）一并复查是否兜底。
3. Carewell 已本轮修正（辅具 / 银发日用 → 银发零售）。

# 四、标签与企业库规则（2026-07-12 v3 重盘新增/更新）

## 标签规则

**一、标签价值定义（定性 + 量化标准）**
- 定性：一个标签的价值 = 让不同企业之间可区分 + 普通用户一眼看懂这家企业在干啥 + 便于搜索/浏览筛选。
- 量化/可判定标准：
  - 区分度：任一二级标签企业数 ≤ 全库约 12%≈160 家，超过即区分度不足须排查错标或拆分（不重要则不精细）。
  - 可懂度：二级标签须是普通用户熟悉常用词，非 jargon、非大伞词。
  - 覆盖度：0 标签企业 = 0，每家企业至少 1 个二级标签。
  - 唯一性：每个二级标签只属于 1 个一级标签（见第四节）。

**二、标签分类归属（评估维度与判断逻辑）**
- 给每个二级标签定一个且仅一个一级标签，判定优先级：**行业 > 业务 > 产品**。
  - 先看"行业"：主营行业清晰（医疗/金融/食品/文娱等）→ 归对应行业一级。
  - 行业不清看"业务"：做什么服务/模式（养老服务/零售渠道/健康管理等）→ 归业务一级。
  - 再看"产品"：卖什么具体东西（辅具/智能硬件/营养品等）→ 归产品一级。
- 走查方法：把全部二级标签**逐个**看一遍，按优先级归最贴切的一级；两 L2 语义相近/重叠 → 合并（留更常用者，别名进同类词）；合并后仍无合适一级 → 可新增一级专门承接。禁止同一 L2 出现在多个一级下。
- 编码落地：规范映射表 `L2_TO_L1`（每个 L2 恰好一个 L1）写在 `_rebuild_tags.py`，重跑后全库企业据此设 `tag_l1`；若企业有 L2=X，则其 `tag_l1` 必含 `L2_TO_L1[X]`。

**三、标签质量检测（发现问题与排查方法）**
- 自动校验：重跑 `validate_tags.py` 9 项全绿为底线（无同类词二级=0、0 标签企业=0、单企业≤5 标签、企业内标签无重复、有标签必有 L1、全部标签在 canon 集合、一级=二级不同名、幽灵≤2 家、同类词无碰撞/孤儿/退化）。
- 分布排查：统计各 L1/L2 企业数，标记 >150 家大桶（区分度风险），优先查桶内错标。
- 重复冗余：查同名/近义 L2 是否应合并；查 L2 是否跨一级出现（违反单归属）。
- 可懂度走查：普通用户视角抽 ≥30 家，看标签能否懂这家干啥，记录"看不懂/对不上"。

## 企业库规则

**二、企业库新增字段：深度文章链接**
- 字段名：`deep_article_links`（深度文章链接）
- 类型：数组，**0~2 条**，按价值降序；无高质量文章时为空数组，不强制提供。
- 用途：AI 在阶段 3/阶段 4 通读搜寻时，若发现高质量第三方文章（企业商业模式深度分析、创始人采访等），存入此字段，供小爽写稿前参考别人写法、找差异化。
- 约束：纯资讯类快讯不纳入（走 `related_news_ids`）；只放深度/长文。

**三、其余字段补全**
- 除「深度文章链接」外，其余企业字段全部在阶段 3、阶段 4 AI 通读环节**一轮补全/校正**。
- （注：13 business_model、17 tags 已废弃，18 category 不动，这三处不补全；其余补。）

**四、二级标签单归属（硬规则）**
- 所有二级标签**只能属于一个一级标签**。建立规范映射 L2→L1（每个 L2 恰好对应一个 L1），全库企业执行此映射；若某 L2 当前跨多个一级出现，须归并到唯一一级并修正相关企业的一级归属。
- v3 现状：已建立 `L2_TO_L1` 单一映射（覆盖全部 56 个二级标签），重跑后全库企业 `tag_l1` 严格按此映射生成；跨一级的 L2 数 = 0，单归属落实。
