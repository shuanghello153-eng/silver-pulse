## 1. 标签到底是什么（本项目定位）

- **用途**：给小爽在 1305 家企业里**快速筛选/浏览**的"可识别分类"——一眼看懂这家干啥、值不值得细看。
- **不用于评分**（已证实）。评分走自己的字段（融资/新闻/联网搜）。
- 因此标签的唯一裁判：**用户能不能用它高效发现/区分企业**。

## 2. 好标签的硬标准（保留有效部分 + 修正）

1. **易懂**：普通用户熟悉的具体词（助听器/认知症/老年鞋），非 jargon、非大伞词。
2. **有区分度**：二级标签企业数 ≤ 全库约 12%（≈160）；>150 进排查。
3. **非空泛（服务谁）**：服务人群标签只在"非显而易见"时才有价值——
   - 全库都服务老人 → "老人"标签无意义；
   - "护理类"本身已含"失能老人" → 不必另标"服务失能老人"；
   - 若某护理企业专做认知症 → 认知症值得标（它把这类和别类护理区分开了）。
4. **不重复**：近义合并（助听器已覆盖多数听力场景，不需再造"听力健康"）；每企业 ≤5 个标签，且每个提供**独立、不冗余**视角。
5. **单归属**：每个二级恰好属于 1 个一级（行业 > 业务 > 产品 优先级）。
6. **≥3 家**；不与卡片已展示字段（融资/地区/成立年）重复。

## 3. 产品形态是合法标签（修正 V1）

- ✅ **保留为标签**：智能硬件、SaaS、AI/人工智能——用户会主动搜"智能硬件企业有哪些"。
- ❌ **不当标签**：底层实现技术（如"用了深度学习""云原生"）——用户不会这么筛。
- 判定口诀：用户会主动按它筛 → 是标签；用户不会按"用了X技术"筛 → 不是。

## 4. 多标签 = 附加视角，不是凑数（用真实数据示范）

- **正确姿势**（库里真实存在）：助听器企业主标 `助听器`，外加它**确实还卖**的 `助行器`/`助听辅具`/`轮椅`。每个都是真实业务。
- **错误姿势**（V1 编造）：把 `助听器` 拆成 `消费品+智能硬件+听力健康`——后两个要么不存在、要么和主标重复、要么虚。

## 5. 我（研究员）与评分 AI 的协作边界

- **我独占**：`tag_l1` / `tag_l2` / `tag_synonyms`（打标规则归我，长期迭代）。
- **评分 AI 独占**：`description`、`funding_*`、`news_coverage`、`highlights`、`value_score`、`recommend`、`deep_article_links`，以及 `business_tags(customer/role/channel)`。
- **桥接字段 = `business_tags`**：评分 AI 填的 customer/role/channel 是"服务谁/做什么"的可靠信号，我打标时**优先消费它**（比假 description 可靠），不再依赖 description。
- **时序**：评分 AI 先补全 business_tags + 真实 description → 我据此重打标签。但我**不必等全部补完**——`name + business_tags` 现在就齐全可用，164 家模板污染企业可立即用这对真实字段重打。
- **防互踩**：两人改同一 `all_enterprises.json`，必须各管各的字段。我的打标脚本只写 tag 三个字段，绝不动评分 AI 的字段；反之亦然。合并靠"各自 patch 自己字段"，而非整文件覆盖。
