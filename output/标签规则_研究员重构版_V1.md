## 一、标签到底解决什么问题（目标）

网站本质是「小爽的选题情报台」。标签只干一件事：

> **让小爽在 1 秒内判断"这家企业/这条资讯我该不该点开细看"，并能在 1305 家里快速筛出某一类。**

由此推导标签必须满足三个用户价值（与评分规则 §8.1 对齐）：
1. **可区分**：同一标签下企业不能太多，否则失去筛选意义（小爽原话："每个标签下企业太多，每个企业就没特点"）。
2. **可懂**：普通用户一眼看懂这家在干啥，不用查 jargon。
3. **可搜可筛**：既能点选筛选，也能搜各种叫法都命中（同类词层）。

标签还直接喂给**评分阶段 4 的"可复制"维度**——国内有没有同类赛道、有没有上亿融资/上市公司，判断准不准取决于标签打没打对。所以标签不是装饰，是推荐质量的地基。

## 二、好标签的标准（我的版本，吸收小爽意见并修正）

在原有 10 条基础上，我做了三处关键修正（理由见第四节批判）：

1. **够具体**：二级标签是能直接搜、有区分度的具体词（认知症 / 助听器 / 老年鞋），不是大伞词、不是横切属性。
   > ⚠️ **修正点**：`SaaS` / `AI` / `智能硬件` / `可穿戴监测` / `跌倒监测` / `远程医疗` 这类"横切属性"——它们描述的是"用了什么技术/怎么交付"，不是"做了什么/服务谁"。一个企业是"助听器厂商"还是"陪诊平台"，不会因为都用了 SaaS 就变相似。**建议把横切属性降级为"业务模式元数据"（business_tags 或新字段），不再占二级标签名额。** 这是当前 8 个大桶（≥40）里一半的根因。
2. **一级 ≠ 二级同名**：容器名和具体词不能一样。
3. **不与卡片已有字段重复**：融资状态、被收购、地区、成立年——卡片自己会显示，不做标签。
4. **同义词并成一个规范词**：别名全进同类词层（只用于搜索）。
5. **每个标签 ≥ 3 家**（「养老」特例见第 11 条）。
6. **每个标签都有同类词**：核心标签必须覆盖常见别名。
7. **每个标签只归一个一级**（L2→L1 单一映射）。
8. **每家企业最多 3 个二级标签**，但**不应只有 1 个**。
   > ⚠️ **修正点**：现状 73% 企业只有 1 个标签（见问题诊断）。单标签=只从一个角度看过这家企业，丢失了跨领域视角（一家助听器公司同时是消费品+智能硬件）。目标：单标签率压到 40% 以下，让"多标签"真正落地。
9. **不用自造词**：新词需小爽确认。
10. **不说黑话**：不用 jargon、英文缩写（CCRC/SaaS 等业界通用除外）、单字碎片。
11. **噪声/大伞词不当标签**：废弃 / 综合养老 / 生态 / 平台 / 礼物 / 国家名 / 地区名 / 品牌名 / 产品名单独，一律不当标签。
    > ⚠️ **修正点**：「养老」目前仅 Carewell 1 家用，且被错误挂在「智能科技」下（config 实证）。它本质是个无意义的大伞词，违反第 1、11 条。**建议删除「养老」标签，Carewell 改回 `电商 + 垂直电商`（或 `零售`），与全库其他零售企业一致。**

## 四、生成流程（修正版，堵住"循环污染"）

**还原的真实链路（批判）**：前序 AI 用 LLM 给 164 家企业生成了"模板化描述文案"（如"面向银发人群的X企业，主营Y业务：..."），随后关键词分类器又**读这些描述回灌标签**——描述写"居家照护"就被标"居家护理"。这是**自证循环**：标签质量取决于假描述的用词，且同一条模板被分散标成 5 种不同标签（实测 17 家同模板→护士上门8/居家护理7/居家医疗3/专业护理2/安宁疗护1）。这就是"拆了又涨"的病根。

**修正后的流程**：
1. **主信号改用可靠字段**：打标优先依据 `name` + `business_tags{customer,role,channel}`（全库 1305 家全有）+ 旧 `category_l1/l2` + 真实结构化字段（融资/地区）。**description 仅当确认非模板文案时才作辅助。**
2. **隔离 164 家模板文案**：要么用真实信源重生成 description，要么在分类时直接排除 description 信号、只用 name/business_tags。
3. **聚类 + 归并**（沿用小爽的方法论 (b)）：关键词聚到 L2 → 二次聚类给跨一级的第二/第三标签（不得落入已有 L1）→ 同义合并、别名进同类词。
4. **产业资本特殊处理**：只保留自身是投资机构/资本方（VC/PE/CVC/REIT/险企/上市集团），与"拿没拿过融资"无关。
5. **落地**：全量重打 → 跑增强版校验 → 写回 `all_enterprises.json` → 重跑 `gen_enterprise.py`+`gen_about.py`+`generator.py`+`gen_deliverables.py` → 部署。

## 五、命名与归属规则（优先级，修正）

一个标签可能跨多一级时，按 **行业 > 领域 > 业务 > 产品** 判定，高优先级命中即停：
- 助听器厂商 → 消费品（行业），不是医疗健康
- 认知症照护 → 医疗健康（领域）
- 养老机构运营 → 养老服务（业务）
- 外骨骼产品 → 康复辅具（产品），不是智能科技

**禁止**因"这家也卖 X 产品"就把 X 所在一级当主一级（产品优先级最低）。落地映射 `_l2_l1.json` 每个 L2 恰好一个 L1。

## 七、改动流程铁律（与协作）

1. **UI 小修直接做**：搜索框、按钮样式、布局——直接改。
2. **标签大改动先对齐**：清洗/合并/重命名/删除——先出方案文档，小爽确认后执行。
3. **每次改完必交付完整结果**：一级列表+企业数、每级二级+企业数、**每个二级的全部同类词（一个不省略）**、改动前后对照。
4. **主动挖错**：不等问题点名，全量排查同类潜在错误。
5. **动过小爽手标的标注【动你标注】+ 理由**，不静默改。
6. **标准动作链**：改 `all_enterprises.json` → 三生成器 → `gen_deliverables.py` → 部署 → commit main。缺一步看不到新标签。
